# SPEC · 11 求职材料岗位对照

目标用户:主动求职的成年人。付款人:求职者本人。大市场、阶段性高频。

## 核心任务(必须跑通)

1. 左侧贴「岗位描述」,右侧贴「简历文本」(纯文本;不解析 PDF/Word)。
2. 关键词提取(确定性):从岗位描述中找「要求行」(含 熟悉/精通/掌握/了解/经验/年以上/优先/required/proficient/experience/familiar 等关键词的行),把每行按 `、,,;/()()` 和「和/与/及/or/and」切成候选词;英文词与缩写(如 `SQL`、`Next.js`、`CI/CD`)整体保留;去掉停用词(了解/熟悉/能力/相关/经验/优先 等)。候选词展示为可勾选的 chip,用户可增删;保存为该岗位的关键词集。
3. 对照:每个关键词在简历里是否出现(大小写不敏感、全半角统一、去空格;支持用户定义同义词组 `JS = JavaScript = 前端脚本`)。输出:覆盖率 = 命中数 / 关键词数;「缺失」清单;「命中位置」(简历中第几行);按「必须(含 精通/required/必须)」与「加分(含 优先/plus)」分组统计。
4. 事实核验清单:自动从简历里抽出所有数字句(含 %、年、人、万、倍、+ 的句子),列成「需要能举证」的清单,用户逐条勾「有证据 / 需修改」。
5. 版本:为同一岗位保存多个简历版本(标题 + 时间 + 全文);任意两个版本做行级 diff(新增/删除/不变着色);每版记录覆盖率,显示趋势条。
6. 导出:对照报告 Markdown(岗位、关键词、覆盖率、缺失、事实核验表);JSON 备份导入。

## 不做

不生成简历内容、不改写句子、不解析文件、不联网查公司。

## core.js 暴露

`extractRequirementLines(text)`;`extractKeywords(lines)` → `[{term, must:boolean}]`;`normalize(s)`;`match(keywords, resume, synonyms)` → `{hits:[{term, lines:[n]}], missing:[...], coverage, mustCoverage}`;`extractFacts(resume)`;`diffLines(a, b)`(LCS 行级);`toMarkdown(report)`;`validateImport(json)`。

## 示例

合成岗位(「对外汉语教师(线上)」+ 一份「前端工程师」两个可切换)与各两版简历,刻意含:同义词(`HSK` vs `汉语水平考试`)、全半角差异、一条无证据的「提升 300%」;标注「合成示例」。

## 测试点(≥ 14)

要求行识别(中英关键词);切词与缩写保留;停用词过滤;must/加分分组;normalize 全半角与大小写;同义词命中;覆盖率计算(0 关键词不除零);命中行号;事实句抽取(百分号、年、万、+);diffLines 新增/删除/相同;版本趋势按时间排序;validateImport 拒绝缺字段;公式前缀防护;`?today`。

## 视觉方向

求职工具感:干净的白 + 一个稳重的蓝绿;关键词 chip 命中为绿、缺失为红(AA);diff 用浅绿/浅红底;手机端左右输入上下堆叠。

## 已知限制(写进 README)

关键词提取是规则切词,不理解语义;同义词靠用户维护;不解析 PDF。
