# 译稿机械检查

交稿前把双语稿过一遍机械一致性:漏译、占位符、数字、术语、长度比、末尾标点、疑似未译、同原文不同译。

## 目标用户与核心任务
翻译工作室审校、独立译者、做双语教材的教师(付款人设想为工作室主理人)。核心任务:导入双语表 → 填术语表 → 运行检查 → 按段落号看问题 → 导出。

## 如何打开
双击 `index.html`(file:// 即可,无依赖、无联网、无登录)。第一步:点「载入合成示例」看完整流程,或把你的双语表粘贴进输入框再点「运行检查」。

## 功能
- 导入:CSV/TSV(段落号、原文、译文)或两个文本框按行对齐(行数不等时给出差异提示)。不合法的表格(列数不对、段落号为空或重复、引号未闭合)整份拒绝并说明原因。
- 术语表:每行 `原文术语 | 允许译法1, 允许译法2`,全角分隔也认;可切换大小写敏感。
- 阻断:漏译、原文为空而译文有内容、占位符集合不一致({0}/{name}、%s/%d、HTML 标签、换行数)、数字集合不一致。
- 警告:术语译法不符、长度比异常(默认 >3 或 <0.3,可调)、末尾标点类型不一致、原文与译文相同(trim 后严格相等)、同原文不同译。
- 统计:段数、漏译数、术语不一致数、占位符问题数等。
- 导出:问题清单 CSV / Markdown、带「问题」列的双语表 CSV(均做公式注入防护)。输入改动后未重新检查时导出禁用。
- 数据存 localStorage(键 `transcheck.v1`);写入失败时显示持续可见的「未保存」提示,并提供「导出当前内存里的全部输入(JSON 备份)」。
- JSON 备份:导出当前输入(双语稿、术语表、选项);导入走「校验 → 预览行数与替换范围 → 确认 → 写入」,不合法整份拒绝。

## 口径
- 段数 = 双语表行数(或两个文本框对齐后的行数);原文和译文都为空的段不检查,仍计入段数。
- 漏译数、占位符问题数、数字不一致数、术语不一致数都按命中的问题条数计;术语不一致按「术语命中」计,一段里两个术语不一致算两条。阻断合计、警告合计按条数计,可以大于段数。
- 长度比 = 译文字符数 ÷ 原文字符数(去掉首尾空白,内部空格和标点计入),默认超过 3 或低于 0.3 报警告;结果提示里也用「字符」。
- 「没有发现问题」只在所有检查完整运行、没有输入错误时显示;有输入错误时写「检查未完成:N 处错误」。
- 输入错误显示在出错的输入框下方(双语表、术语表、长度比上下限、文件选择),并聚焦第一个出错控件;顶部只有一句补充说明。
- 载入示例、导入文件(双语表)、导入 JSON 备份、清空前的确认判据:双语表或两个文本框里的内容、术语表、偏离默认的选项(大小写敏感、长度比)、当前检查结果;确认文案写明被替换的范围。
- 示例标记只在双语表与合成示例完全相同时显示(刷新后仍在);导出的问题清单 CSV(多一列「数据来源」)、双语表 CSV、Markdown 都标注「合成示例」;改动、清空或导入后消失。
- 安全核对(2026-10-20):`app.js` 全部用 `textContent` / `createElement` 渲染,没有 `innerHTML` 拼接。

## 已知限制
- 只做机械一致性,不判断译文是否准确,不自动翻译,不处理 docx。
- 术语按字面子串匹配,不做词形变化与分词(如 `cat` 会命中 `category`,复数不会命中单数以外的变形)。
- 长度比按字符数计算(不是词数或字数),中英互译的正常比例差别大,默认阈值对英译中偏严,需按语言对调整。
- 数字只识别阿拉伯数字(含全角),不识别中文数字或英文数词;小数点与千分位逗号不做区域格式换算。
- 末尾标点分问号/感叹/句号/无句末标点四类,类型不同就报警告(「句号 ↔ 无标点」也报,标题类短句会有误报,可忽略)。
- 同原文判断是整段文字(忽略空白差异)完全相同,不做模糊匹配。
