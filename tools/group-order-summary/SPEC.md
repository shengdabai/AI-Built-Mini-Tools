# SPEC · 34 团餐点单汇总

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:小团队的「点餐负责人」、班级/社团活动组织者、家庭群买菜的人。付款人:本人(高频日常)。

## 核心任务(必须跑通)

1. 菜单:粘贴菜单(`菜名 | 单价 | 可选规格(逗号分隔)`),或手动加;支持别名(`宫保鸡丁=宫保, 鸡丁饭`)。
2. 收集回复:粘贴群聊文本(「名字: 菜名 x2 微辣」「名字 菜名」「名字: 不吃」「名字: 同上」),解析规则:名字 + 分隔符 + 内容;数量 `x2`、`2份`、`两份`(中文数字到十);规格匹配菜单的可选规格;「同上」取前一人;「不吃/不要」记为不点;未识别菜名 → 「待确认」;同一人多次回复取最后一次。
3. 汇总:按菜名 × 规格合计数量与金额;按人列清单(菜、数量、规格、应付);总金额;待确认列表(菜名无法匹配 / 数量不明)。
4. 输出:商家下单文本(「宫保鸡丁 微辣 ×3,不辣 ×2 …」);收款文本(「张三 25 元,李四 18 元 …」);可配 AA(把配送费/包装费按人头或按金额比例分摊)。
5. 历史:每天一单,保存;「上次同款」一键复制昨天的点单;本周每人点单次数与金额。
6. 导出:汇总 CSV;下单/收款文本;JSON 备份。

## 不做

不接外卖平台、不收款、不做菜单抓取。

## core.js 暴露

`parseMenu(text)`;`parseReplies(text)`;`parseQty(text)`;`matchDish(text, menu)`;`aggregate(orders, menu, options)` → `{byDish, byPerson, total, pending}`;`splitFee(byPerson, fee, mode)`;`orderText`;`paymentText`;`weekStats(days)`;`toCsv`;`validateImport`。金额整数分。

## 示例

合成菜单 12 道(3 道有规格)+ 一天 16 条回复(含 x2、两份、同上、不吃、未知菜、一人改单、规格写法不一);标注「合成示例,姓名虚构」。

## 测试点(≥ 12)

parseMenu 别名与规格;parseQty 各写法;matchDish 精确/别名/包含/歧义;「同上」;「不吃」;最后一次优先;aggregate 合计与金额;pending;splitFee 两种模式与余数分配(总额守恒);orderText/paymentText;weekStats;CSV 公式防护;空回复。

## 视觉方向

点餐清单感:白 + 深橙红;金额右对齐;手机优先(负责人多用手机),桌面两栏。

## 已知限制(写进 README)

匹配是启发式;不处理一人代点多人。
