# 团餐点单汇总

## 定位

粘贴菜单和群里的回复,自动合计每道菜的份数与金额、每人应付多少,并生成给商家的下单文本和给同事的收款文本。纯前端,双击 `index.html` 即可使用,数据只存在本机浏览器(localStorage 键 `tuancan.v1`)。

## 目标用户
小团队的点餐负责人、班级/社团活动组织者、家庭群买菜的人。

## 核心任务
1. 菜单:粘贴 `菜名=别名1, 别名2 | 单价 | 规格1, 规格2`,或手动添加。
2. 收集回复:粘贴「名字: 菜名 x2 微辣」「名字 菜名」「名字: 不吃」「名字: 同上」;数量支持 `x2`、`×2`、`2份`、`两份`(中文数字到十);同一人多次回复取最后一次;认不出的进「待确认」。
3. 汇总:按菜名 × 规格合计,按人列清单与应付,总金额,待确认列表。
4. 输出:商家下单文本、收款文本;配送费/包装费可按人头或按金额比例分摊(总额守恒)。
5. 历史:每天一单;「上次同款」复制之前最近一天;本周(周一至周日)每人次数与金额。
6. 导出:汇总 CSV(按菜、按人)、下单/收款文本、JSON 备份(导入需通过校验,整份通过或整份拒绝)。

## 如何打开
双击 `index.html`。演示可加 `?today=2026-10-20` 固定「今天」(非法日期如 `2026-02-30` 回退真实今天)。点「载入示例」查看完整流程(合成示例,姓名虚构)。

## 口径(SPEC 未规定,本实现的选择)
- 一人点多道菜用逗号、顿号、分号或加号分隔;空格不作分隔。
- 菜名匹配优先级:精确 > 文本包含菜名/别名 > 菜名包含文本;同级且同长度命中多道菜记为歧义,进待确认。
- 单独一段只写了上一道菜的规格(「宫保鸡丁, 微辣」)并入上一道。
- 「同上」取文本中紧邻的上一位有效回复(链式成立);上一位不吃则同样不吃;前面没人则待确认。
- 不点的人不分摊费用;按金额比例分摊时若全部金额为 0 则退回按人头;余数按最大余数法/先后顺序分配。
- 为防止数值溢出设了上限:单价 ≤ 10 万元、费用 ≤ 100 万元、单条数量 ≤ 999、一天回复 ≤ 20 万字、菜单 ≤ 300 道、历史 ≤ 3700 天;保存前与读取后使用同一份校验。
- 名字取第一个冒号(: 或 :)之前,没有冒号则取第一个空白之前。
- 每日订单保存当天的菜单快照:改菜单只刷新「今天」及之后日期的快照,更早的日期保持原价和原菜名,周汇总与历史金额不随之变化;「上次同款」和新建日期按当前菜单计价。查看过去的日期时无法给它加新菜。快照随 JSON 备份一起导出,缺少快照的旧备份会被拒绝。
- 查看历史日期时,菜单框显示该日保存的菜单快照(只读,并标明日期);只有快照与当前菜单不同时才出现这个提示。「编辑当前菜单」按钮切换到当前菜单,此时说明该日汇总仍按快照计价,应用菜单不改变该日金额。
- 费用输入非法时,汇总、下单文本、收款文本仍是上一次保存的费用算出来的结果,页面说明这一点,并停用复制与 CSV 导出,修正费用后恢复。
- 零头规则:按人头平分时,分不尽的 1 分按名单顺序先给前面的人;按金额比例时,先给小数余数较大的人,余数相同按名单顺序。页面上的说明随分摊方式切换。
- 「已有数据」(载入示例、导入、清空前要确认)= 已保存的菜单与历史,加上尚未应用的菜单修改、「手动加一道菜」表单里没提交的内容。确认文案写明菜单道数、历史天数和草稿。
- 同一人最后一条回复若无效(只有名字、只有数量、没有名字后的内容等),该人订单置为待确认,不再沿用他更早的有效回复;被后来的有效回复取代的无效行不再列出。
- 周统计的金额含分摊费用;只统计有已确认菜品的天数。
- CSV 里以 `=`、`+`、`-`、`@`(及制表符、回车)开头的用户字段加单引号前缀;单独的 `-`/`+` 不加。

## 已知限制
- 匹配是启发式的,请核对待确认列表。
- 不处理一人代点多人。
- 回复里带时间戳(如「12:30 张三 ...」)会被当成名字的一部分或冲突,需先删掉。
- 菜名里含「份/个/碗」前缀数字的写法(如「两个鸡蛋」)可能被当作数量。
- 不接外卖平台、不收款、不抓菜单;无多设备同步,换设备请用 JSON 备份。
- 浏览器复制被拒绝时,文本会被选中,需手动 Ctrl/Cmd+C。
