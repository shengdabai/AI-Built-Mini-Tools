# 报价版本差异说明

## 定位
把旧版、新版两份报价表按项目编码对比,生成给客户看的「新增 / 删除 / 调整」变更说明,并保存版本对比与客户确认记录。纯前端,数据只存在本机浏览器。

## 目标用户
装修、设计、软件外包工作室的销售与项目负责人;付款人设想为工作室主理人。

## 核心任务
1. 粘贴或选择旧版、新版 CSV/TSV(第一行为表头),确认列对应(项目编码必选)。
2. 对比:新增、删除、数量/单位/单价变更、名称变更(仅提示);显示旧值 → 新值、金额影响、旧合计/新合计/差额/变化百分比。
3. 生成可编辑的 Markdown 变更说明,可勾选「只列影响金额的项」。
4. 保存版本对比记录(时间、版本名、差额、是否已向客户确认与确认日期),按时间排成版本链。
5. 导出:差异表 CSV、变更说明 Markdown、JSON 备份。

## 如何打开
双击 `index.html`(file:// 即可,无需联网、无依赖)。地址后加 `?today=2026-10-20` 可固定「今天」。点「载入合成示例」走完整流程,「错误示例」演示重复编码报错。

## 功能要点
- 重复编码、缺编码、非法数字、引号未闭合(整份表格拒绝)会阻止计算并报行号;金额四舍五入到分;旧合计为 0 不计算百分比。
- 输入框里已有报价文本或版本名时,点两个示例按钮会先出现页内确认区,确认前不改动也不保存任何内容。
- 输入或列对应改动后结果标记过期,导出与保存被禁用,须重新对比。
- 存储写入失败时显示持续可见的「未保存」提示并引导导出 JSON。
- JSON 导入严格校验(类型、日期、id 唯一),不合法整份拒绝并给原因。
- CSV 导出对以 `=`、`+`、`-`、`@` 开头的文本字段加单引号前缀。

## 口径
- 差额 = 新版合计 − 旧版合计;变化百分比 = 差额 ÷ 旧版合计,旧版合计为 0 时不计算并写明原因;金额影响 = 数量 × 单价的变化,四舍五入到分。
- 说明草稿:变更说明文字(含手动编辑)随输入自动保存到本机浏览器,并包含在 JSON 备份的 `draft.explainText` 里;编辑区下方显示保存状态,保存失败时写明未保存。刷新后还没有重新对比时,草稿仍显示,但标为「尚未对应最新对比」,导出禁用。手动编辑过的说明不会被重新对比悄悄覆盖,会保留并提示,点「重新生成」才覆盖。
- 记录的保存时间用同一个时区生成,格式如 `2026-10-20T16:05:09+08:00`,历史记录里写明 UTC 偏移与时区名;地址带合法 `?today=` 时日期部分取固定日期,记录标注「日期由地址参数固定,为模拟日期」。旧版本保存的没有偏移的记录标注「旧记录,未记录时区」。版本链按绝对时刻排序。
- 「业务基准日」在确认记录表单旁持续显示;地址带合法 `?today=` 时写明「由地址参数固定」,确认日期默认取这一天。
- 导入 JSON 备份:校验通过后先显示现有记录数、备份文件记录数和编辑区草稿的替换范围,页内确认后才写入。
- 载入合成示例后页面持续显示「合成示例」标记(随草稿保存,刷新后仍在),导出的文件名与内容带「合成示例」;清空或导入真实备份后消失。

## 已知限制
- 依赖两版的项目编码一致;编码改了会被当成一删一增。
- 不识别图片、PDF、Excel 二进制,只处理 CSV/TSV 文本。
- 百分比对 0 基数不计算。
- 不做合同条款、电子签。
- 备注列不参与差异判断。
- 本机存储的旧数据若格式不合法会被忽略并在下次保存时覆盖。
- 示例两版为 14 行与 15 行(2 新增 1 删除,无法同时各 14 行)。
