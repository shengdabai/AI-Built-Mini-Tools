# SPEC · 48 写作复售账本

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:写作者、课程作者、独立开发者;付款人:本人。

## 核心任务(必须跑通)

1. 作品录入:标题、类型(文章 / 课 / 书 / 视频 / 代码库)、首次创作耗时(小时)、创作日期;每次「再售」记录:日期、渠道(可配:公众号 / X / 邮件 / 书 / 课 / 演讲 / 其他)、形式(原发 / 改写 / 合集 / 翻译 / 口播)、额外耗时(小时)、触达(可选数字)、收入(可选,整数分)、交易引用(可选可打印 ASCII 订单代号,禁止客户信息;中文说明写入其他笔记)。
2. 复售指标:每部作品「被售次数」、累计耗时、「每小时被售次数」= 次数 ÷ (首次 + 额外耗时);有收入时算「每小时收入」;无收入只显示次数口径,不编造。
3. 可视化:作品 × 月份的复售热力格(div);每部作品的「时间投入 vs 售出次数」散点(SVG,点大小 = 触达);渠道分布条形。
4. 规则提示:创作 > 90 天且仅售 1 次 → 「可改写 / 合集 / 翻译」候选清单(按类型给固定建议文案);同一作品同渠道的交易引用经首尾去空格和 ASCII 大小写归一后必须唯一,冲突阻止保存或导入;非 ASCII 与控制字符直接拒绝;无引用记录仅在日期、渠道、形式、额外耗时、触达、收入全部相同时提示疑似重复;额外耗时 > 首次耗时 → 提示「这不是复售是重做」。
5. 月报:本月新作品数、复售次数、每小时被售次数 vs 上月。
6. 导出:作品表 CSV、月报 Markdown、JSON 备份;导入校验(类型/渠道/形式枚举、小时非负、金额整数)。

## 不做

不接平台数据、不估算流量价值。

## core.js 暴露

`resaleCount(work)`;`hoursTotal(work)`;`perHour(work)`;`heatmap(works, months)`;`scatter(works)`;`channelStats(works)`;`hints(works, today)`;`monthly(works, month)`;`compare(a,b)`;`toCsv`;`toMarkdown`;`validateImport`;`?today`。

## 示例

合成 7 部作品(文章 4、课 1、书 1、代码库 1)、31 条再售记录,其中 1 部 > 90 天只售 1 次、1 条同月同渠道重复、1 条额外耗时超首次;部分有收入(虚构);标注「合成示例,金额虚构」。

## 测试点(≥ 12)

resaleCount;hoursTotal 含额外;perHour 除零(耗时 0 → null);无收入不输出每小时收入;heatmap 月序;scatter 点数;channelStats;三条规则各一例;monthly 与 compare;`?today`;CSV 公式防护;枚举校验;写读校验同源。

## 视觉方向

白 + 深紫(非渐变);热力格 token 色阶;手机端单列。

## 已知限制(写进 README)

触达与收入自填;「被售」只是记录次数,不证明有人付费。
