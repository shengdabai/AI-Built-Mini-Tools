# AI 订阅成本账本

## 定位
把每月的 AI 订阅花费和「这个月用 AI 完成了多少工作」放在同一张账上:订阅折成月成本,按用途填自估的小时当量,算每小时当量成本并与机会成本时薪比较。

## 目标用户

## 核心任务
1. 订阅录入:服务名、档位、币种、金额、周期(月付/年付/一次性/按量)、开始日、续费日、状态(在用/暂停/已退)、用途标签、谁在用(自己/团队 N 人);按量订阅可录每月实际账单。
2. 月成本:年付按 1/12 折月,一次性按摊销月数平均,按量取当月实际;多币种各自汇总、不换汇;可填一个折算汇率,仅用于总览,并标「估算」。
3. 产出挂接:每月按用途填小时当量与一句证据;每小时当量成本 = 月成本 ÷ 小时当量,与机会成本时薪比较(低于/高于);不填产出只显示成本。
4. 提醒:续费日 0–7 天内;连续 2 个月产出为 0 的在用订阅「考虑暂停」;同一用途 ≥ 3 个在用订阅「重叠」。
5. 趋势:近 12 个月成本柱(div 高度为运行时数据)+ 小时当量折线(运行时生成的 SVG 线段与 div 点),本月 vs 上月。
6. 导出:订阅表 CSV、月报 Markdown、JSON 备份;JSON 导入严格校验,整份拒绝并给原因。

## 如何打开
双击 `index.html`(file:// 即可,无需安装、无需联网)。地址后加 `?today=2026-10-20` 固定「今天」;非法日期(含 2026-02-30)回退真实今天。点「载入示例」看完整流程;已有数据时载入示例、导入、清空都先在页内确认。

## 口径(SPEC 未规定,本实现的选择)
- 成本有两种口径。已有月度成本快照的月份使用快照;没有快照的月份按订阅当前状态推算。暂停或已退的订阅不再进入推算,但不会改写快照。固定月费、年付和一次性费用按月摊销；按量费用取已录账单。两种口径都不是程序核验的实付支出。
- 快照不会自动生成。用户必须选择月份,对照账单核对程序列出的订阅明细,再填写确认日期和来源。程序保存的是当时的订阅 id、服务名、用途、币种和金额;同一个月份再次保存会显式更新原快照。
- 未来月份、未来确认日期不能保存或导入。缺少适用按量账单时拒绝保存快照；明确为 0 的账单会保留明细。旧快照缺完整性字段时持续提示无法确认当时是否缺账单。
- 新增、退订或改价不改原币快照。换汇估算仍按当前汇率计算，并在月报中说明。
- 小时当量 = 折合人工小时:估计不用 AI、自己完成这些交付物需要多久,不是使用 AI 的时长。每小时当量成本 = 月成本 ÷ 折合人工小时(总览的该数字旁有同样说明)。
- 删除月账单、产出记录、订阅都先在页内确认;确认文案写明订阅/用途、月份、金额或小时,确认前数据不变。
- 年付与一次性的月成本各自四舍五入到分,全周期合计可能与原价差几分钱。
- 「产出为 0」指该用途在该月有一条小时当量为 0 的记录;没有记录视为未填,不算 0。产出按用途记录,所以同用途的订阅共用同一份产出;「连续 2 个月」指今天所在月与上一个月,且订阅开始月不晚于上一个月。
- 多币种且没设折算汇率时,总览不给整体比值(各币种共用同一份小时当量,分币种相除没有意义);设了汇率后给估算比值。时薪只与同币种的数值比较。
- 只要有币种没被折算汇率覆盖(例如只配了 USD→CNY 却有 EUR 成本),就不输出总体每小时成本和时薪结论,改为列出缺失币种。
- 编辑产出按原记录 ID 更新;改后的月份+用途已被另一条记录占用时,页内提示冲突,不覆盖。
- 续费日已过会单独提示「续费日已过」,不自动顺延。
- 同一月份同一用途只保留一条产出记录(再次提交即更新);导入含重复会被拒绝。
- 校验上限:服务名/档位 200 字、证据 1000 字、金额不超过 10000000000.00、小时当量不超过 100000、摊销月数 1–120、团队人数 1–10000。
- 导出 CSV/Markdown 表格里以 = + - @ 开头的用户文本加单引号前缀(单独的 - 或 + 不算)。

## 已知限制
- 小时当量是自估;汇率估算只用于总览。
- 不接账单 API、不换汇、不评价模型优劣。
- 快照金额来自保存当时账本的月成本计算,程序不读取信用卡或服务商账单。确认来源是用户填写的证据说明,不是程序验证过的外部凭证。
- 每个月最多一份快照;如需保留两种会计口径,应先导出 JSON 备份再更新。
- 浏览器清除站点数据会丢失记录,请定期「备份 JSON」。
- 没有 CSV 导入;没有多人协作。
