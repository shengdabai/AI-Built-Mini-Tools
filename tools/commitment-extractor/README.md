# 承诺跟进提取器

## 定位
把群聊记录和会议纪要里「我来」「周五前」「I'll send」这类承诺，变成一张可编辑、可导出日历的跟进清单；没说清的承诺（「回头」「soon」「那个色卡」「the revised sample」）单独标成「待澄清」，并用原句的语言生成追问。纯前端、固定规则、不联网、不调用 AI。

## 目标用户
- 在微信 / 飞书 / WhatsApp 群里和海外供应商、客户对接交付的小团队负责人
- 每周整理会议纪要、盯交付日期的项目协调人
- 不愿把聊天记录交给第三方 AI 服务的人

## 核心任务
粘贴一段中英混合的聊天或纪要 → 确认基准日期 → 得到「谁、做什么、哪天交」的清单，标出哪些承诺还需要追问 → 改正误判 → 把追问发回群里，把有日期的承诺导进日历。

## 如何打开
双击 `index.html`（Chrome / Edge / Safari 均可，`file://` 直接运行，无需安装、无需联网）。没有材料时点右上角「载入示例」。

## 功能
- **四种输入格式**：`张三：…`、`[10:32] 李四: …`、`王五 10:32` 换行后跟正文（到空行为止）、无说话人的纪要条目（`- 供应商会在下周一前寄出样品`）。
- **承诺识别（中英）**：第一人称承诺（我来 / 我负责 / 我把…发你 / I'll / I will / Let me）、指派（`@周启 你来…`；`请苏蔓…` / `麻烦欧阳娜…`：「请 / 麻烦 + 2–3 个汉字 + 期限或动作词」，被指派人不必在别处发过言；`请问 / 请大家 / 请尽快 / 请各位 / 请你 / 请把…` 等在停用表里，不当成人名）、第三方（`供应商会…`、`Minh to share…`）。负责人分别取说话人、被指派人、句首主语；「大家 / 有人 / 团队」不算具体负责人；纪要里只写名（Minh）且发言人里有唯一全名（Minh Tran）时归并到全名。问句先于指派判断，`@周启 你来处理吗？` 这类问句不进清单；问句和闲聊（「中午吃什么？」「我去吃个饭」「The weather is great today」）不计入。
- **日期换算（相对基准日期）**：今天 / 明天 / 后天 / 大后天 / 下班前 / EOD、周X（含今天的下一个）/ 本周X / 下周X、月底 / 本月底 / 下月底、10月9日 / 10/9（无年份 M/D：月 1–12、日须在该月存在；年份规则同「X月X日」：早于基准日 180 天以上才推到明年；前后紧挨数字、`/`、`.`、`:`，或后面跟 `%` / 量词（`3/5家`、`1/2页`）时视为比例不当日期）/ 2026-10-09、X号（滚动到下一个有这天的月份，30号会跳过二月）、by Friday / next Monday / tomorrow / end of month。跨周、跨月、跨年、闰年都有测试。换算不了的一律留空，不猜。
- **待澄清判断**：缺负责人、缺期限、期限含糊（回头 / 尽快 / 改天 / 下周 / soon / later / ASAP 等）、指代不明（那个 X / 这个 X / the revised X 等）。编辑后实时重算：只要事项里还含原句的完整模糊短语（「那个色卡」「the revised sample」）就保持标记；补上负责人和日期、改写成具体描述（「B 款灰色色卡」「sample v2」）后，标记自动消失。
- **追问生成**：按原句语言出中文或英文问题，例：`We need the revised sample soon.` → `Which revision of the sample should we confirm, and what date can you commit to?`；「复制全部问题」一键复制。
- **原文对照**：承诺句用实线下划线 +「承诺」文字标签，待澄清句用虚线框 +「？待澄清」文字标签（不只靠颜色）。点清单行或「第 N 行」定位到原句并闪烁提示（尊重 prefers-reduced-motion）。
- **可编辑清单**：负责人 / 事项 / 期限 / 状态（待办 · 已完成 · 已取消）可直接改；逾期（期限早于今天且仍待办）用红色边框 +「逾期」文字标签；按负责人、状态、清晰度筛选；全部存在本机 localStorage（键 `cfx:state:v1`），刷新不丢。重新识别时按字段保留人工编辑：只改了状态的行，期限仍按新基准日期重算；手动改过的期限才保持不变。匹配先按 id；原文前面插了行导致 id 变化时，按「说话人 + 原句」回退匹配（新旧两边都唯一才认，重复句不猜）。旧版数据里的 `edited: true` 不知道改过哪个字段，按四个字段都改过处理（宁可少重算，不丢编辑）。
- **本机数据保护**：启动时深度校验存储（顶层、筛选、每条事项的字段类型与取值）。JSON 解析失败或结构有问题时，先把原始字符串备份到 `cfx:state:v1.corrupt-<时间戳>`，页面顶部常驻红色 `role="alert"` 提示写明备份键，启动阶段不写回正式键；备份也失败时暂停一切写入，直到用户「清空数据」。写入失败时显示常驻「未保存」提示，「识别出 N 条」等成功提示只在写入成功后出现。
- 「载入示例」：只要输入框、已识别原文或清单任一非空就先确认；取消则什么都不改。
- **导出**：CSV（UTF-8 BOM，Excel 直接打开不乱码；防公式注入：跳过开头空白 / 换行 / 控制字符后首字符为 `= + - @`（含全角）即加 `'` 前缀）、Markdown 跟进纪要（统计 + 承诺表格 + 需要追问的问题；所有动态字段与追问文本编码 `& < >`，不输出原始 HTML）、`.ics` 日历（RFC 5545：全天事件、CRLF 换行、UID、DTSTAMP、文本转义、75 字节折行且不切断中文；只收有日期且未取消的承诺）。
- 「清空数据」先弹确认；界面常驻提示「规则识别会漏判和误判，请人工核对」。

## 已知限制
- 固定规则，会漏判和误判。已知误判：`我明天休息` 会被当成承诺；`我把报价发你了`（已完成的过去式）会被当成待办；`the updated X` 会被标成指代不明。已知漏判：没有承诺词的隐含承诺、跨多条消息才说完整的承诺、代词型负责人（「他来弄」）、没有承诺词的简短说法（「本月底我提交」）、英文代词指代（`send it ASAP` 只标期限含糊，不标 it 指代不明）。
- 无年份 `M/D` 与比例写法有歧义：紧邻「比分 / 比例 / 占比 / 完成了」或英文 `ratio / score`（可隔空格及冒号或等号）时不当日期，后接百分号或已列出的量词也不当日期。「进度 / progress」后默认按比例处理；若日期后紧跟「前交 / 前提交 / 前完成」等明确交付提示（可隔空格，也认「之前 / 以前」），则按日期处理。没有这些上下文的 `已做1/2` 仍可能被当成日期；只按 月/日 解析，不支持 日/月 顺序。
- 「请 + 名字」只认 2–3 个汉字的中文名且后面紧跟期限或动作词；英文名、4 字以上名字、「请老板…」这类称谓会被当成名字或漏判。
- 不支持中文数字日期（「三号」「十月九日」）、「月初 / 月中 / 上旬」、具体时刻（只到日，日历导出为全天事件）；单独的「下周 / next week」按期限含糊处理而不是猜某一天。
- 说话人识别依赖行首格式；一行多人、引用回复、转发嵌套不会拆分。
- 未做笔记要求的「20 个标注承诺 ≥18 个正确」真实数据准确率测试——手头没有授权的真实聊天，只有合成示例。
- 不接飞书 / 微信 API，不自动提醒、不发消息；数据只在当前浏览器的 localStorage，换浏览器或清缓存即丢失，请用导出备份。
- 截图里的日期输入框显示格式跟随浏览器语言（无头浏览器下为 mm/dd/yyyy）。
