# SPEC · 28 项目毛利表

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:自由职业者、小工作室、接项目的个体。付款人:本人。

## 核心任务(必须跑通)

1. 项目录入:名称、客户、报价(含税/不含税开关 + 税率)、状态(报价中/进行中/已交付/已收款/已取消)、开始/交付日期。
2. 成本行:类型(人工小时 × 时薪 / 外包 / 工具与订阅(按月分摊:月费 × 占用月数 × 分摊比例)/ 差旅 / 其他)、金额、备注。人工时薪有「机会成本时薪」默认值(用户设)。
3. 计算:收入(不含税)、直接成本、毛利、毛利率、每小时毛利(毛利 ÷ 总人工小时)、「低于机会成本时薪」警示;付款条件:预付比例、尾款账期天数 → 预计回款日;回款日 < 今天且状态非已收款 → 逾期。
4. 组合视图:全部项目毛利率排序;按客户汇总(总收入、平均毛利率、项目数);本季度 vs 上季度(按交付日期);「最差 3 个项目」与「共同特征」(只列客观字段:客户、类型、时薪,不下结论)。
5. 情景:拖动「时薪」「报价折扣」两个滑块,实时看毛利率变化(纯计算,div 宽度=运行时数据)。
6. 导出:项目表 CSV;单项目毛利说明 Markdown;JSON 备份。
7. 估算与实际:用户可锁定带版本号的估算基线;锁定后继续编辑不得改写旧基线。显式重开会保留旧版并创建新草稿版本。实际工时按整数分钟记录,并保存当条时薪;实际费用和实际收款按整数分记录。三类记录都必须包含真实日期、3 位大写币种代码、来源和备注。
8. 完整性与偏差:缺少的实际值是未知,不是 0。只有活动基线已锁定、截至日内实际记录币种均与基线一致,并且用户明确声明截至日数据完整时,才计算估算与实际的收入、成本和毛利偏差。截至日之后的记录保留但排除出本次合计与偏差。声明必须有真实截至日和声明日,满足「截至日 ≤ 声明日 ≤ 运行当天」。新增或删除实际记录必须撤销旧声明。报价与实际收款保持两个概念;不扩展到应收账款或银行对账。

## 不做

不做发票、不做工时打卡、不做税务申报。

## core.js 暴露

`netRevenue(quote, taxIncluded, rate)`;`costTotal(lines)`;`margin(project)` → `{revenue, cost, gross, rate, hours, perHour, belowOpportunity}`;`dueDate(project)`;`isOverdue(project, today)`;`portfolio(projects, today)`;`byClient(projects)`;`quarterCompare(projects, today)`;`scenario(project, {hourly, discount})`;`lockEstimate`;`reopenEstimate`;`actualComparison`;`toCsv`;`toMarkdown`;`validateImport`。金额用整数「分」计算,实际工时用整数分钟。

## 示例

合成 9 个项目、4 个客户,含含税/不含税混合、1 个低于机会成本、2 个逾期、1 个已取消、跨两个季度;标注「合成示例」。

## 测试点(≥ 12)

含税换算;成本分摊;毛利率除零;perHour 无人工小时;机会成本警示;dueDate 预付+账期;逾期边界(当天不算);portfolio 排序;byClient 汇总;季度边界;scenario 折扣与时薪;`?today`;CSV 公式防护;validateImport 状态枚举;整数分精度;旧备份只迁移估算;锁定基线不可变;重开版本保留历史;基线版本号唯一且锁定日不早于创建日;未知实际不按 0;截至日过滤;完整性日期顺序;部分费用不显示偏差;报价与实收分离;币种不兼容不合并;实际记录日期、ID、金额和分钟严格校验;JSON/CSV/Markdown 往返包含全部币种、日期、来源、备注与单位。

## 视觉方向

财务表格感:白 + 深绿;负毛利红字;手机端卡片。

## 已知限制(写进 README)

不做税务;分摊规则是用户自设的近似值。
