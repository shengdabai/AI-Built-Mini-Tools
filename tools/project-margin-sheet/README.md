# 项目毛利表

## 定位
接项目的个人和小工作室用的纯前端小工具:录入报价、成本和付款条件,算出每个项目的毛利、毛利率、每小时毛利和预计回款日,并在组合视图里比较项目、客户和季度。

## 目标用户
自由职业者、小工作室、接项目的个体。付款人是本人。

## 核心任务
1. 项目录入:名称、客户、报价(含税/不含税 + 税率)、状态、开始/交付日期、预付比例、尾款账期。
2. 成本行:人工(小时 × 时薪)、外包、工具与订阅(月费 × 占用月数 × 分摊比例)、差旅、其他。
3. 计算:不含税收入、直接成本、毛利、毛利率、每小时毛利、低于机会成本时薪警示、预计回款日、逾期。
4. 组合视图:毛利率排序、按客户汇总、本季度 vs 上季度、最差 3 个项目与共同特征。
5. 情景:时薪与报价折扣两个滑块实时试算。
6. 估算与实际:把当前报价和预计成本锁定为版本化基线;记录带日期、币种、来源和备注的实际工时、实际费用与实际收款;用户明确声明记录完整后才计算偏差。
7. 导出:项目表 CSV、单项目毛利说明 Markdown、JSON 备份(可导入)。三种格式都包含基线、实际记录、完整性和单位口径。

## 如何打开
双击 `index.html`(file:// 可用,无需联网、无依赖)。地址后加 `?today=2026-10-20` 可固定「今天」;格式不对或日期不存在(如 2026-02-30)时回退真实今天。点「载入示例」可看 9 个合成项目。

## 功能与测试
- 存储键 `margin.v1`。写入失败时显示持续可见的「未保存」提示并引导导出;保存前与读取时使用同一个 `validateState`。
- 导入校验失败整份拒绝并给原因;已有数据时「载入示例」「导入」「清空」,以及删除项目、删除成本行,都先出页内确认(成本行的确认就在该行下方,写明小计会从直接成本里扣除)。
- 任一输入框内容未通过校验(标红)时,项目里保留的是旧值,此时 CSV、Markdown、JSON 导出按钮禁用并提示;改正或切换项目撤销该输入后恢复。
- 导出防公式注入:以 `=` `+` `-` `@` 开头的用户字段加单引号前缀(单独的 `-`/`+` 不算)。
- 测试:`node --test tests/core.test.cjs`(32 个用例)。既有截图与端到端检查:`node shots.cjs`;估算与实际专项检查:`node tests/actual-ui.cjs`。

## 口径(SPEC 没有规定,由实现者自定)
- 金额以整数分计算,四舍五入取半入;含税换算 = 报价 ÷ (1 + 税率),税率最多两位小数。
- 单个金额字段上限 100 亿元(1e12 分),单行算出的金额也不得超过此值,是为了保证整数精度。
- 人工成本按所填时薪计入直接成本;「每小时毛利」= 毛利 ÷ 总人工小时,与项目上的机会成本时薪比较,严格小于才警示。新项目的机会成本时薪默认 150 元/小时,可在页面改。
- 预计回款日 = 交付日期 + 尾款账期天数;预付比例 100% 时 = 开始日期;缺日期则无法计算。逾期 = 回款日 < 今天(当天不算)且状态不是「已收款」,另外「已取消」也不计逾期。逾期金额 = 报价 ×(1 − 预付比例),假设预付款已收到。
- 已取消项目不进入排序、客户汇总、季度对比和最差 3 个。季度按交付日期的日历季度,没有交付日期的不参与。
- 毛利率排序从高到低;报价为 0 的项目毛利率为空,排最后。
- 客户汇总同时给「平均毛利率」(各项目毛利率的算术平均)和「加权毛利率」(总毛利 ÷ 总收入)。
- 「最差 3 个」取毛利率最低的 3 个;共同特征只列客户、成本类型、人工成本时薪、含税情况等客观字段。
- 情景:时薪滑块把该项目所有人工行的时薪换成滑块值;折扣滑块(0–50%)按比例降低报价;都不改动项目数据。
- 毛利 = 不含税收入 − 直接成本,直接成本已含人工费;每小时毛利 = 毛利 ÷ 总人工小时,是「扣掉人工费之后每个人工小时剩多少」,不是实际时薪,用来和机会成本时薪(把这些小时用在别处能赚的钱)比较。
- 季度对比的说明区分三种情况:某季度没有项目、某季度收入为 0 无法算毛利率、可比较(给出百分点差)。
- 地址带有效 `?today` 时页头持续显示「基准日 YYYY-MM-DD(由地址参数固定)」。示例项目名称带「(合成示例)」,随数据保存、随导出文件带出。
- 允许保存半成品(空名称、空日期、报价为 0)。
- 锁定基线是报价、税率、机会成本时薪和预计成本行的不可变快照。继续编辑当前项目不会改写旧基线;“创建新估算版本”会复制最近的锁定基线为新草稿,再次锁定后形成下一版本。
- 实际人工成本 = 整数分钟 × 该条记录的整数分时薪 ÷ 60。实际费用与实际收款也用整数分。每条实际记录必须有真实日期、3 位大写币种代码和来源。
- 缺少的实际记录是未知,不是 0。只有活动基线已锁定、截至日内所有实际记录币种与基线一致,并且用户明确声明截至日记录完整时,才显示收入、成本和毛利偏差。新增或删除实际记录会自动撤销旧声明。截至日之后的记录保留在明细和备份中,但不计入该截至日的合计与偏差。
- 完整性声明必须同时包含真实的截至日和声明日。截至日不能晚于声明日,声明日不能晚于运行当天。
- 报价是不含税估算收入的输入;“实际收款”才表示用户记录的已收金额。本工具不处理应收账款、催收或银行对账。不同币种分别保留,不自动换算或合并。

## 已知限制
- 不做发票、工时打卡、税务申报;含税换算只是粗略估算。
- 工具订阅的分摊比例是用户自设的近似值。
- 可以记录不同币种,但不会自动换算或合并;没有多人协作。数据只在本机浏览器,清除站点数据会丢失,请定期导出 JSON。
- 只有一个税率口径(整单一个税率)。
- 终端侧测试用 Playwright 的 headless shell,未在 Safari/Firefox 实测。
