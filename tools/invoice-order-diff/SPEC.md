# SPEC · 07 发票与订单差异核对

目标用户:小型贸易 / 服务公司财务、代账人员。付款人:财务负责人或企业主。原则:只输出待复核清单,不自动付款、不自动申报。

## 核心任务(必须跑通)

1. 两个输入区:「订单表」与「发票表」,各支持粘贴 TSV/CSV(自动识别分隔符:制表符、逗号、分号)或选择本地文件。解析用自写 RFC 4180 解析器(可从 06 的思路实现,但代码各自独立)。
2. 列映射:解析后显示表头,用下拉为每个角色选列。订单角色:订单号(必选)、品名、数量、单价、金额(必选)。发票角色:发票号(必选)、订单号(必选)、品名、数量、单价、税额、金额(必选)。自动猜测(列名含「订单/PO」→订单号,含「发票」→发票号,含「金额/合计」→金额,等),用户可改。
3. 核对参数:金额容差(绝对值,默认 0.01)与百分比容差(默认 0.5%),满足其一即视为一致;税率期望值(默认 13%,可改,留空则不查税);是否按「订单号+品名」匹配(默认只按订单号;同一订单多行时按品名二次匹配,匹配不上再按顺序)。
4. 核对结果(每条带级别与原行号):
   - 阻断:发票的订单号在订单表不存在;同一发票号出现多次;金额差超容差;数量差;单价差。
   - 警告:订单无对应发票;税额与「金额 × 税率」偏差超容差;发票金额合计与订单金额合计不等(汇总级);品名不一致(按订单号匹配到但品名不同)。
   - 正常:一致的配对也列出,可折叠。
5. 汇总卡:订单数、发票数、已配对、阻断数、警告数、订单金额合计、发票金额合计、差额。
6. 导出:待复核清单 CSV 与 Markdown(含参数);全部配对结果 CSV。公式前缀防护。

## 不做

不做 OCR、不连财务软件、不做付款与申报、不保存上传的文件(仅本次会话内存;「示例」可存 localStorage)。

## core.js 暴露

`parseTable(text)`;`guessMapping(headers, role)`;`normalizeNumber(s)`(支持 `1,234.50`、`¥`、`￥`、全角数字、括号负数);`reconcile(orders, invoices, mapping, options)` → `{pairs, issues, summary}`;`toCsv(rows)`;`toMarkdown(result, options)`。

## 示例

合成:12 条订单、13 条发票,刻意含:金额差 2 元、数量差、重复发票号、无订单的发票、无发票的订单、税额错(按 9% 开的)、品名有半角/全角差异;标注「合成示例」。

## 测试点(≥ 14)

分隔符识别(制表/逗号/分号);normalizeNumber 各格式与非法值;guessMapping 命中与未命中;容差边界(恰好等于容差视为一致);百分比容差;重复发票号;缺订单;缺发票;数量差;税额检查与留空跳过;同订单多行按品名匹配;汇总差额;CSV 导出转义与公式防护;空表不报错。

## 视觉方向

财务工作台感:墨绿 + 浅灰,数字右对齐 `tabular-nums`;左右两栏输入,下方结果;手机端上下堆叠。

## 已知限制(写进 README)

匹配依赖订单号字段准确;不识别发票图片;金额容差是用户设置,不是会计准则。
