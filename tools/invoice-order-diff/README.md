# 发票与订单差异核对

## 定位
把订单表和发票表按订单号配对,按阻断/警告分级列出差异,生成带原行号的待复核清单。只输出待复核清单,不自动付款、不自动申报。

## 目标用户
小型贸易 / 服务公司的财务、代账人员;付款人是财务负责人或企业主。

## 核心任务
1. 左右两栏粘贴订单表与发票表(制表符/逗号/分号自动识别,自写 RFC 4180 解析器),或选择本地文件(只在本页内存读取,不保存;非 UTF-8 时尝试按 GBK 解码)。
2. 下拉确认列映射(自动猜测,可改)。订单表必选:订单号、金额;发票表必选:发票号、订单号、金额。
3. 设置金额容差(绝对值,默认 0.01)、百分比容差(默认 0.5%,与绝对值满足其一即一致)、税率(默认 13%,留空不查税)、是否严格按「订单号+品名」匹配。
4. 查看汇总卡与待复核清单;一致的配对可折叠查看。
5. 导出待复核清单 CSV / Markdown(含参数)与全部配对结果 CSV。

## 如何打开
双击 `index.html`(file:// 即可,无需安装、无需联网)。点「载入示例」查看完整流程。

## 核对规则
- 阻断:发票订单号不在订单表(或为空);同一发票号出现多次;金额差超容差;数量不一致;单价不一致(单价按保留六位小数后的值比较,不使用金额容差);同订单下发票行多于订单行。
- 警告:订单无对应发票;税额偏离「金额 × 税率」超容差;发票与订单金额合计不等(汇总级);品名不一致。
- 品名比较做全角/半角与大小写归一后再比,所以「ＵＳＢ键盘」与「USB键盘」视为一致。
- 同订单多行:先按品名配对,再按顺序;严格模式下不做按顺序配对。
- 解析校验:任一表有引号未闭合、或某行列数与表头不一致,整次核对被拒绝并提示行号,导出按钮禁用(带逗号的金额请用引号包起来)。
- 订单号为空的订单行不参与配对,但金额仍计入订单合计,并单独警告。
- 单价按保留六位小数后的值比较,不使用金额容差;汇总合计差额不为 0(按分)即警告,不用配对容差。
- 订单号比较忽略大小写、空白、全角半角。

## 口径
- 汇总卡里的「订单行数」「发票行数」「已配对行数」按数据行计数;同一订单号有多行时每行分别计数。金额单位是元,取所选「金额」列(请选不含税金额),不能识别为数字的金额不计入合计;差额 = 发票金额合计 - 订单金额合计。
- 待复核清单 CSV 每行都带金额容差、百分比容差、税率期望值、匹配模式四个参数列;Markdown 的「核对参数」段同义。载入合成示例后,CSV 多一列「数据来源:合成示例」,Markdown 顶部写明数据来源。
- 载入示例前,只要有粘贴的表或改过的核对参数,就先在页内确认,确认文字写明替换哪些内容。「清空数据」会同时清空两张表及核对参数。

## 已知限制
- 匹配依赖订单号字段准确;不识别发票图片,不做 OCR,不连财务软件。
- 金额容差是用户设置,不是会计准则。
- 按规格,同一发票号出现多次一律阻断;一张发票含多条明细行时需先合并明细,否则会被标为重复。
- 税额检查假设「金额」为不含税金额。
- 不保存上传的文件;刷新页面后输入的表需重新粘贴(仅示例可恢复)。
- 数量与单价必须完全相等;只有金额使用容差。
- 无 ?today 参数(本产品不涉及日期计算)。
