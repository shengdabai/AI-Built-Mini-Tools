# 配方缩放器

## 定位
录入一份配方,按目标产量,或按「我只有 350g 面粉」这类某一配料的目标数量反推倍数,一次算出所有用量。

## 目标用户
烘焙爱好者、小餐饮、手作工作室。付款人:本人。

## 如何打开
双击 `index.html`(file:// 即可,无依赖、无联网、无登录)。点右上角「载入示例」看完整流程。

## 核心任务
1. 录入配方:每行 `名称 | 数量 | 单位 | 备注`,支持批量粘贴;数量支持 `1/2`、`1 1/2`、`2-3`(范围,两端分别缩放)、全角数字、「半」;「适量」等非数值原样保留并标「不缩放」。也能粘贴「面粉 500g」「500 g 糖」。
2. 缩放:按目标产量,或按某一配料的目标数量反推倍数。
3. 单位智能:同量纲自动升降(1500 g → 1.5 kg,0.25 L → 250 mL),可关;计数单位同时给精确值与取整值;杯、勺只在同单位内缩放。
4. 烘焙百分比:选基准配料(面粉)后显示百分比;也可由百分比与基准重量反向生成新配方。
5. 导出:Markdown(打印友好)、CSV、JSON 备份;导出内容与界面结果一致,倍数无效时导出按钮停用。
6. 配方库:本机保存(localStorage 键 `recipescaler.v1`),可搜索;清空前有页内确认。自动保存的草稿允许名称暂时为空,刷新后照常恢复;再次载入示例时若示例配方已存在,先页内确认再覆盖;原始产量填 0 或非法文本时显示错误,修正前不计算结果、不允许导出。

分数运算用有理数(BigInt),显示可选小数(最多 2 位)或分数(分母不超过 16 时)。
CSV 与 Markdown 导出对以 `=`、`+`、`-`、`@` 开头的用户字段加单引号前缀。导入 JSON 做类型、单位枚举、ID 唯一性校验,不合法则整份拒绝并给出原因。存储写入失败时显示持续的「未保存」提示并引导导出。

## 文件
`core.js` 纯逻辑 / `app.js` 界面 / `styles.css` 样式(顶部 TOKENS) / `sample-data.js` 合成示例 / `tests/core.test.cjs` / `shots.cjs` / `showcase.html`。

## 口径
- 备份、自动保存和导入共用同一份数据契约:配方名称可以为空(草稿),类型、长度、单位枚举、ID 唯一性仍严格校验;导出的备份一定能再导入。
- 导入先校验,再显示「新增 N 份、覆盖 M 份同 ID 配方」及名单,点「确认导入」才写入;取消则现有配方不变。
- 删除单份配方前,确认区写明配方名与会一并删除的配料数;清空前写明配方份数。
- 「倍数」= 目标产量 ÷ 原始产量,或 目标配料数量 ÷ 原配料数量(同单位换算后);倍数无效时不显示旧值,导出停用。
- 烘焙百分比 = 配料重量 ÷ 基准配料重量 × 100;只统计质量单位。
- 本产品不涉及「今天」的计算,没有 `?today` 参数;备份文件里的 exportedAt 取本机当天。

## 已知限制
- 不做容积与质量互换(杯、勺、mL 与 g 之间不换算,烘焙百分比里容积配料不计入)。
- 烘焙时间与温度不随份数缩放,页面与导出里有提示,需人工调整。
- 不做营养计算、不联网搜菜谱。
- 单位限于固定列表;粘贴时无法识别的单位会记入备注并给警告。
- 范围值不能用来反推倍数;烘焙百分比的基准配料必须是单一的质量单位数值。
- 数据只在当前浏览器的本机存储里,换浏览器或清缓存会丢失,请用 JSON 备份。
