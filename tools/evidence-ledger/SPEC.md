# SPEC · 05 证据台账


## 核心任务(必须跑通)

1. 新建研究项目(标题、问题、日期)。
2. 在项目下添加主张(claim):一句话陈述;状态由规则自动算,不手选(见规则);可手写置信度备注。
3. 给主张挂证据:类型(官方文档 / 一手数据 / 二手转述 / 个人观察 / AI 生成),立场(支持 / 反对 / 不相关),强度(强 / 中 / 弱),来源标题、URL(可空)、摘录、日期、局限说明。
4. 主张列表:显示状态徽章、支持/反对计数、「缺一手证据」警示、「仅有 AI 生成证据」警示;可按状态和警示过滤;搜索。
5. 检查页:一键列出全项目的问题:无证据的主张、只有 AI 生成证据的主张、有强反对但状态仍为「已支持」的主张(规则下不可能出现,列为 0 时也显示)、URL 为空的非个人观察证据。
6. 导出:Markdown「依据与局限」段(可直接贴进研究 HTML):每条主张 → 状态 → 证据列表(类型 / 立场 / 来源 / 局限);JSON 备份与导入(校验)。

## 不做

- 不抓网页、不验证 URL 可达、不调 AI、不做多人。

## 规则(core.js 必须实现并测试)

- 状态:无证据 → 「待验证」;有任一「强」反对 → 「已反驳」;否则有任一非 AI 生成的支持证据 → 「已支持」;否则(只有 AI 生成的支持,或只有弱/中反对)→ 「不确定」。
- 「缺一手证据」= 没有类型为官方文档或一手数据的证据。
- 「仅 AI」= 证据非空且全部为 AI 生成。
- `core.js` 暴露:`status(claim)`;`flags(claim)`;`audit(project)`;`toMarkdown(project)`;`validateImport(json)`;`search(project, q)`。
- 保存:localStorage 键 `evidence.v1`;多个项目。

## 示例(载入示例)

1 个合成研究项目(主题:「某教学工具是否值得做」),5 条主张覆盖四种状态与两种警示,9 条证据;标注「合成示例」,URL 用 `https://example.com/...`。

## 测试点(≥ 12)

四种状态各一;强反对压过支持;只有 AI 支持 → 不确定;缺一手证据判定;仅 AI 判定;audit 四类问题各一;Markdown 含每条主张与局限;search 大小写不敏感且搜摘录;validateImport 拒绝缺 claims 字段与非法类型值;删除证据后状态重算;空项目 audit 不报错。

## 视觉方向

档案/台账感:冷灰蓝底 + 白卡,状态徽章四色(AA 对比),AI 生成证据有明显但不刺眼的边框标记;手机端列表单列。

## 已知限制(写进 README)

不验证来源真伪;规则是本工具的约定,不是通用学术标准。
