# SPEC · 35 AI 答案核实清单

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:用 AI 做研究、写稿、做决策的人。付款人:本人。

## 核心任务(必须跑通)

1. 新建核实任务:问题、AI 答案(粘贴)、模型名、日期。
2. 拆断言:用户把答案拆成逐条「断言」(或一键按句号/换行粗拆后手动合并);每条断言字段:类型(事实 / 数字 / 引用 / 推断 / 建议)、可核实性(可查 / 需实验 / 无法核实)、状态(未核 / 已核实 / 有误 / 存疑)、证据(来源文本 + URL http(s))、备注。
3. 规则:「事实/数字/引用」类断言未核实时,整份答案状态为「不可引用」;有误断言 ≥ 1 → 「需修正」;全部可查断言已核实 → 「可引用」。无法核实的断言不计入分母但在报告里单列。
4. 拷问生成:按三个固定模板生成下一轮提示词(可复制):① 自我批判(「列出上述答案中最可能错的三处及理由」);② 改进而非推翻(「保留结论,只修正第 N 条断言」);③ 交叉模型(「以下是模型 A 的答案,请逐条指出错误并给来源」)。轮次记录:第几轮、用哪个模板、结果摘要。
5. 统计:断言数、各状态数、核实率、每轮修正数;「错误率」按模型汇总(跨任务)。
6. 导出:核实报告 Markdown(断言表 + 证据 + 结论状态);CSV;JSON 备份。

## 不做

不调用任何模型 API、不联网核实、不评判答案质量。

## core.js 暴露

`splitClaims(text)`;`validateClaim`;`answerStatus(claims)` → `{status, reasons, verifyRate}`;`probePrompt(kind, context)`;`roundStats(rounds)`;`modelStats(tasks)`;`toMarkdown`;`toCsv`;`validateImport`(URL 仅 http(s))。

## 示例

合成 2 个任务:一个关于「某历史年份与数字」的答案(含 2 条有误、1 条存疑、1 条无法核实)、一个关于「技术建议」的答案;两轮拷问记录;标注「合成示例,内容为示意」。

## 测试点(≥ 12)

splitClaims 粗拆;类型/状态枚举;answerStatus 三种结果与无法核实不计分母;核实率除零;probePrompt 三模板含上下文;roundStats;modelStats 跨任务;URL 校验拒绝 javascript:;Markdown 结构;CSV 公式防护;validateImport;空任务。

## 视觉方向

审稿工具感:白 + 深紫;状态用图标 + 文字;手机端单列。

## 已知限制(写进 README)

核实靠人;工具只强迫你把「信」改成「查」。
