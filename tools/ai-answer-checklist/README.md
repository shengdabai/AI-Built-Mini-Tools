# AI 答案核实清单

## 定位

把「信」改成「查」:把 AI 的答案拆成逐条断言,逐条核实,再决定能不能引用。纯前端,不联网,不调用任何模型 API。

## 目标用户
用 AI 做研究、写稿、做决策的人。付款人:本人。

## 核心任务
1. 新建核实任务:问题、AI 答案、模型名、日期。
2. 拆断言:按句号/换行粗拆(或手动添加),可与上一条合并;每条有类型(事实/数字/引用/推断/建议)、可核实性(可查/需实验/无法核实)、状态(未核/已核实/有误/存疑)、证据来源文本、证据链接(仅 http/https)、备注。
3. 结论状态:见「口径」。
4. 拷问:三个固定模板(自我批判、改进而非推翻、交叉模型)生成可复制的提示词;记录第几轮、用哪个模板、修正几条、结果摘要。
5. 统计:断言数、各状态数、核实率、每轮修正数;按模型汇总错误率(跨任务)。
6. 导出:核实报告 Markdown、断言 CSV、JSON 备份;可导入 JSON 备份。

## 如何打开
双击 `index.html`(file:// 即可)。数据存在浏览器 localStorage(键 `answercheck.v1`)。地址后加 `?today=2026-10-20` 可固定「今天」;非法或会自动进位的日期(如 2026-02-30)回退真实今天。

## 口径(SPEC 未规定,由实现者定,供人类复核)
- 结论状态优先级:有误断言 ≥ 1 为「需修正」(优先于「不可引用」,原因列表里会同时写出未核实的关键断言);否则事实/数字/引用类的可查断言有未核实(未核/存疑)为「不可引用」;否则推断/建议类仍有未核实为「核实中」;全部可查断言已核实为「可引用」。没有断言为「待拆断言」;没有任何可查断言时为「核实中」。
- 「无法核实」的断言不计入核实率分母,也不触发「不可引用」,但在原因与报告里单列,提示引用时注明。
- 核实率 = 已核实的可查断言 ÷ 全部可查断言(可查 + 需实验);分母为 0 时显示「—」。页面和报告里核实率旁都写出分子、分母(例如「2 ÷ 3」)和无法核实的条数。界面里的「已核实」数量包含无法核实类里已核实的断言,所以不能直接用它除以断言数。
- 模型错误率 = 有误 ÷ (已核实 + 有误);未核与存疑不进分母。模型名首尾空格忽略,空名归入「(未填模型)」。
- 粗拆:按 。!?;、换行拆分,英文句点仅在后跟空白时算句末;不设最短长度,不去重。合并:文本用「,」连接,证据与备注用「;」连接;两条证据链接不同时,保留前一条链接,后一条链接写入证据文本,不丢失;两条状态不同则重置为「未核」。
- 已核实、有误或存疑的断言一旦修改断言文字,状态自动重置为「未核」并标注「待重新核实」,保留旧证据并记下被核实时的原文(JSON 字段 `staleFrom`);重新选择状态后标注消失。把文字改回原样不会自动恢复原状态。报告和 CSV 的状态列写成「未核(待重新核实)」。
- 拆断言之后又修改了答案文字,页面提示已有断言可能不再对应当前答案(JSON 字段 `claimsAnswer` 记录断言对应的答案文字),点「确认断言仍对应当前答案」后提示消失。
- 证据链接改动后,「打开证据链接」按钮立即指向新地址;链接为空或不是 http(s) 时按钮隐藏。
- 导出的单元格以 = + - @ 开头(单独的 - 或 + 除外)加单引号前缀;Markdown 表格还转义 `|` 并把换行改为空格。
- 导入只接受本工具导出的 JSON(`app: answer-check`,`version: 1`);任何字段类型、枚举、ID 重复、非 http(s) 链接问题都整份拒绝并给原因。保存前与读取后使用同一个校验函数。
- 拷问提示词:答案、模型、问题、断言、模板、对方答案或任务任一变化,已生成的提示词立即作废,复制按钮禁用;复制前再核对生成时的输入,不一致则拒绝复制。
- 载入示例、导入、清空、删除都有页内确认;已有数据时载入示例不会直接覆盖。

## 已知限制
- 核实靠人;工具只强迫你把「信」改成「查」,不判断答案质量,也不联网查证。
- 不能解析 CSV 导入;只能导入 JSON 备份。
- 复制提示词依赖浏览器剪贴板权限,失败时会选中文本请手动复制。
- 数据只在本机浏览器,清理站点数据会丢失,请定期导出 JSON。
