# SPEC · 03 试课跟进看板

## 2026-10-29 联系事件契约

`contactEvents` 是沟通证据；`stageHistory` 是阶段变更，两者独立。快速联系只写日期。完整联系必须有渠道、摘要和结果。最近联系由有效事件与未核实旧锚点的最晚日期推导。更正只允许一条线性链，每个原事件最多一个替代者，禁止重复 ID、自引用和循环。归档保留历史。导入任一记录非法时整份拒绝，不修改当前状态。JSON/CSV/Markdown 保留事件来源和归档状态。周范围沿用“往前 7 天且含两端”，不能称为最近 7 个日历日期。


## 核心任务(必须跑通)

1. 新建线索:姓名(或代号)、来源渠道(学员推荐 / 社群 / 网站 / 平台 / 其他自填)、首次联系日期、所在时区(文本)、学习目标(HSK 备考 / 生活口语 / 商务 / 文化 / 其他)、阶段、最近联系日期、下一步动作 + 计划日期、报价金额与币种、备注。
2. 阶段固定 7 个:咨询中 → 已约试课 → 已试课 → 已报价 → 已付款 → 已开课;流失(可从任何阶段进入,必须选流失原因:价格 / 时间冲突 / 没回复 / 选了别人 / 其他)。
3. 看板:按阶段分列(流失单独一列),卡片显示姓名、渠道、距最近联系天数、下一步与日期;阶段变更用卡片上的「推进到…」下拉,不做拖拽。
4. 超期提醒:距最近联系 > N 天(N 默认 3,可设)或下一步计划日期已过的线索在顶部「今天要跟」区列出,按逾期天数降序。
5. 统计:各阶段数量;漏斗转化率:咨询→试课、试课→付款、整体咨询→付款;按渠道的线索数与付款数;流失原因分布。全部用页内条形(div 宽度按比例,比例是运行时数据不是设计值)。
6. 导出:周报 Markdown(本周新增 / 本周试课 / 本周付款 / 待跟进清单,「本周」= 今天往前 7 天);全部线索 CSV;JSON 备份与导入。

## 不做

- 不发消息、不接日历、不做多教师、不拖拽。

## 规则(core.js)

- 「今天」可由 `?today=YYYY-MM-DD` 固定;所有天数计算用整数天(按本地日期差)。
- 超期 = (今天 − 最近联系日期) > N 或 (下一步日期存在且 < 今天),已付款/已开课/流失阶段不算超期。
- 转化率分母为「曾到达该阶段的线索数」,用线索的 `stageHistory`(每次推进记录 `{stage, date}`)计算,不只看当前阶段。
- `core.js` 暴露:`advance(lead, stage, date, lossReason?)`;`overdue(leads, today, n)`;`funnel(leads)`;`byChannel(leads)`;`lossReasons(leads)`;`weeklyReport(leads, today)`;`toCsv(leads)`;`validateImport(json)`。

## 示例(载入示例)

14 条合成线索,覆盖所有阶段、4 个渠道、3 种流失原因、至少 3 条超期;标注「合成示例」。

## 测试点(≥ 12)

advance 写入 stageHistory 且不能回退到更早阶段(回退要显式 `allowBack`);流失必须带原因否则抛错;超期两种条件;已付款不超期;转化率按 stageHistory 而不是当前阶段;渠道统计;流失原因分布;周报 7 天边界(第 7 天算、第 8 天不算);CSV 转义;导入校验;`?today` 固定;空列表统计不除零。

## 视觉方向

看板感:浅灰底(不是米白)+ 每阶段一个克制的色条;卡片紧凑;逾期用暖色标签;手机端各列纵向堆叠并可折叠。

## 已知限制(写进 README)

无提醒推送;无多人协作;时区只是文本记录,不换算。
