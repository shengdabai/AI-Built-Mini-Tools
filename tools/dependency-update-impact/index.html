粘贴输入

支持三种格式,自动识别:旧、新两份 package.json(依次粘贴);git diff package.json 的输出(git 的改动对比);npm outdated 的表格(npm 列出可更新依赖的命令)。

名词解释
  • 语义化版本(semver):版本号写成 主.次.补丁。主版本(major)变化可能有破坏性变更,次版本(minor)是新增功能,补丁(patch)是修复。
  • dependencies / devDependencies:运行时依赖 / 只在开发和构建时用的依赖。
  • CHANGELOG:包作者写的版本变更记录,本工具不联网读取。
  • npm outdated 的三列:Current 是已安装版本;Wanted 是在 package.json 现有范围内能装到的最高版本;Latest 是 registry(包仓库)上的最新发布版本,可能跨 major。

当前输入是合成示例,包名与版本均为虚构。导出的 Markdown 和 CSV 也会标注。修改、清空或载入你自己的内容后这条提示消失。

    这些数字怎么算的

    每个依赖按「旧版本 → 新版本」比较一次,计一项变化;同一个包只计一项。分类按版本号最高变化的位置:主版本变化为 major,次版本变化为 minor,补丁变化为 patch;0.x 版本和预发布版本、git 地址、workspace: 等无法比较大小的写法单独归类。「需要重点关注」是 major、降级、预发布、非 semver、重复声明、移动区块这几类的合计。没有检测到变化时,表示两边的依赖版本写法完全相同。
