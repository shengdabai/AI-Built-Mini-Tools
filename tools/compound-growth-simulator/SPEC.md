# SPEC · 42 复利成长曲线模拟器

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:想算清「每天一点点」到底值多少的人;付款人:本人。李笑来启发式 1「先问可以算出来吗」。

## 核心任务(必须跑通)

1. 参数面板(全部滑杆 + 数字输入双向联动):日成长率 r(0–3%,步长 0.01)、时长 T(30–3650 天)、起点 1.0;可加「中断」:每周休息 N 天(休息日 r=0)、一次性回退事件(第 D 天乘以 k)。
2. 曲线:运行时生成内联 SVG 折线,X 轴天数、Y 轴倍数;同时画「线性增长」(每天 +r)对照线;鼠标/触摸悬停显示该天倍数(纯 DOM tooltip);手机端竖排。
3. 对照表:给定 r,列出 T = 100 / 365 / 1000 / 3650 的倍数与「相当于线性的几倍」;给定目标倍数(如 10×),反算需要的天数(`daysToReach`)。
4. 情景比较:最多 3 组参数并排(不同颜色),显示「同一 T 下倍数差」与「达到 2× 所需天数差」。
5. 「每周进步一点点也比没进步强」:切换周频(每周一次 r₇)与日频,给出等效换算 `(1+r)^7 - 1`。
6. 导出:当前情景参数与 365 点序列 CSV;情景 JSON 备份;导入校验(r 范围、T 整数、事件日 ≤ T)。

## 不做

不接任何真实资产数据、不给投资建议、不做收益承诺;页面固定提示「这是数学演示,不是预测」。

## core.js 暴露

`simulate({r, days, restDaysPerWeek, events[]})` → `{series:[{day, value}], final}`;`linear(r, days)`;`daysToReach(r, target, restDaysPerWeek)`;`weeklyEquivalent(r)`;`compare(scenarios)`;`toCsv`;`validateImport`。浮点保留 6 位小数,不用金额整数分。

## 示例

内置 3 情景:「每天 1%」「每天 0.3% 休两天」「每天 1% 第 200 天回退 ×0.7」;标注「合成示例」。

## 测试点(≥ 12)

simulate 基础(r=0 恒 1;r=1% 365 天 ≈ 37.78);休息日跳过;事件回退;linear 对照;daysToReach 可达与不可达(r=0 → null);weeklyEquivalent;compare 排序与差值;series 长度 = days+1;validateImport 拒绝 r>3%、T 非整数、事件日越界;CSV 公式防护(情景名);浮点精度边界(r 极小)。

## 视觉方向

白底 + 深蓝主线、灰线性对照;SVG 由运行时数据生成(无图表库);正文 ≥ 16px;手机单列,图表宽度 100%。

## 已知限制(写进 README)

模型是理想化指数增长;真实成长不是每天等比;演示用途。
