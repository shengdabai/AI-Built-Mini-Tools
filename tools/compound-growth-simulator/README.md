# 复利成长曲线模拟器

## 定位
把「每天进步一点点」算出来:调日成长率、时长、休息日和倍率事件(第 D 天乘以 k,k 小于 1 表示回退、大于 1 表示增长),曲线即时重画,并与线性增长对照。这是数学演示,不是预测,不接任何真实资产数据,不构成投资建议。

## 目标用户
想算清「每天一点点」到底值多少的人(付款人:本人)。

## 核心任务
1. 滑杆 + 数字输入双向联动调参(r 0–3%、T 30–3650 天、每周休息 0–6 天、倍率事件的日期与 k,全部有滑杆)。
2. 内联 SVG 曲线(Y 轴可切对数/线性),灰色虚线为线性对照,悬停/触摸读数。
3. 对照表(T = 100/365/1000/3650)与目标倍数反算天数。
4. 最多 3 组情景并排比较(同一 T 的倍数差、达到 2× 的天数差)。
5. 周频(每周一次 r₇)与日频等效换算 `(1+r)^7-1`,可叠加周频曲线。
6. 导出第 1–365 天 CSV(固定 365 个点,不覆盖完整 T)、全部情景 JSON 备份;导入整份校验。

## 如何打开
双击 `index.html`(file:// 即可,无依赖、无联网)。测试:`node --test tests/core.test.cjs`。截图:`node shots.cjs`。

## 口径(SPEC 未规定,由实现者选定)
- 倍数保留 6 位小数;周频等效等比率保留 12 位小数。r 以小数存储。
- 休息日:每周最后 N 天(第 8−N…7 天)不增长;线性对照同样跳过休息日。
- 倍率事件(原称回退事件)在当天增长之后乘以 k;k 小于 1 是回退,大于 1 是增长;同一天多个事件相乘。事件 k 在界面限 0.01–10,核心只要求 >0。
- 周频:每满 7 天乘一次 (1+r₇),忽略休息日;r₇ 范围 0–25%。
- 比较:统一取各情景 T 的最小值;「达到 2×」按各自参数从第 1 天算。
- 反算天数(`daysToReach`):最后一个事件日之前逐日模拟,之后用对数公式 `ceil(ln(目标/当前)/ln(1+r))` 求增长日数再换算成含休息日的天数;不设天数上限(r=1e-7 到 2× 约 693 万天),只有 r=0 且事件也无法增长时返回「达不到」。界面的反算结果不含回退事件。
- 溢出防护:导入与读取存储时,逐日模拟结果必须全部是有限数且不下溢为 0(例如事件乘数 1e308 会被整份拒绝);界面里多个事件累积导致溢出时,图表显示提示而不是绘图,且该状态不会被保存。
- 「载入示例/导入」是否需要确认,取决于内存里是否已有用户数据或修改,不依赖保存是否成功。
- CSV 固定输出第 1–365 天,不随当前 T 抽样,也不覆盖完整 T;第 365 天之后的倍率事件不会进入这份序列(CSV 说明行和界面按钮旁都写了)。名称以 `= + - @` 开头会加单引号前缀。
- Y 轴默认对数刻度:相同高度差表示相同倍数变化;线性刻度:相同高度差表示相同数值变化(界面在刻度选择旁说明)。
- 删除当前情景先在页内确认,写明情景名、r、T 与事件数;确认前数据不变。
- 休息天数限 0–6;情景最多 3 组;JSON 含 app/version 字段,不合法整份拒绝。
- 数据存 localStorage 键 `compound.v1`;写入失败显示持续的「未保存」提示。

## 已知限制
- 模型是理想化的指数增长;真实成长不是每天等比;仅供演示。
- 图表悬停读数仅支持鼠标/触摸,没有键盘方式(数据可在对照表与 CSV 中读取)。
- 超过约 1e6 倍后数字用科学计数法显示。
