# 本机笔记全文检索

## 定位

给有大量本地 .md / .txt 笔记的人(Obsidian / Logseq / 纯文本用户)用的浏览器内全文检索:选一个文件夹,在内存里建倒排索引,按段落搜索。只读文件,不改写、不同步、不联网。

## 目标用户

有大量本地笔记、想要市面软件没有的检索口径的个人;付款人是本人。

## 核心任务

1. 导入:「选择文件夹」(webkitdirectory)只读 .md/.txt/.markdown,可在「额外后缀」追加;也可「选择文件」或把多个文件拖入。显示文件数、总字数,分批读取并显示进度。
2. 建索引:中文按字二元组、英文按词(小写、去标点);记录路径与段落号。索引可缓存到 IndexedDB,下次打开直接搜,界面显示索引日期。
3. 搜索:空格 = AND;`"引号"` = 连续短语;`-词` = 排除;`path:日记/` = 路径前缀(相对所选文件夹)。结果按命中密度 + 标题命中排序,片段前后各 60 字并高亮,可展开整段与上下段。
4. 工具:关键词共现词前 20(停用词可配);最近修改文件列表。
5. 导出:搜索结果 Markdown(带路径与段落号);索引统计 CSV。

## 如何打开

双击 `index.html`。无需安装、联网、登录。「载入示例(合成)」载入 15 篇合成笔记。地址加 `?today=2026-10-20` 固定索引日期(非法或不存在的日期回退真实今天)。设置存 localStorage(键 `notesearch.v1`),索引存 IndexedDB(库 `notesearch.v1`)。

## 口径(SPEC 未规定处,本实现的选择)

- 字数 = 去掉所有空白后的字符数;段落 = 以空行分隔的文本块。
- 英文词按整词匹配(搜 note 不命中 notes);含中文的词、短语按原文子串验证;孤立单字也能搜(全量扫描)。
- 排序分 = 命中次数 ÷ max(段落字数, 40) × 100,标题或文件名命中再加 5;同分按路径、段落号升序。
- 共现词:同段落去重计数;关键词自身的二元组不计;单字停用词会过滤含该字的二元组,多字停用词整词过滤。
- `path:` 多次出现时取最后一个;大小写不敏感。导入时去掉所选文件夹的根目录名。
- 替换已有索引(载入示例、重新选文件夹、清除)前先在页内确认,确认前保持原状。
- 读取失败的单个文件会被跳过并显示数量。

- 排序口径:分数 = 命中次数 ÷ max(段落字数, 40) × 100,标题或文件名命中再加 5 分;分数相同按路径、段落号排。界面在结果数量旁和「结果是怎么排序的」展开说明里写明。
- 共现词旁的数字 = 该词与关键词同时出现的段落数,同一段里重复出现只计 1 次;中文按相邻两个字的组合(二元组)统计。
- 停用词是不参与统计的词;加入单字(如「的」)时,所有含该字的两字组合也被排除。

## 已知限制

- 文件夹选择依赖 webkitdirectory(桌面 Chromium/Safari/Firefox 可用,多数手机浏览器不支持)。
- 超大库(> 2 万文件)可能慢;索引在主线程构建,期间页面会短暂卡顿。
- IndexedDB 缓存可能被浏览器清理;失败时降级为仅内存并显示持续警告。
- 文件有变更需重新选择文件夹重建,不做增量更新。
- 拖入只处理文件,不展开文件夹。
- 示例库为合成内容。
