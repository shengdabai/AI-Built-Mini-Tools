# 复利墙 · CompoundWall

> 一面安静的修行墙。记录每日微小的重复，见证复利的力量。
> 日拱一卒，功不唐捐。

---

## 一、产品来源：把李笑来的「复利叙事」产品化

李笑来反复讲过两组数字，几乎是他最高频、最自带传播力的核心论点：

- **「106 天读完 5 部大部头」** —— 不是某一天的英勇，而是「每一天」都翻开书。
- **「18 年每天写三千字」** —— 时间这位朋友，替坚持的人做了复利。

他对「重复」的定义尤其关键：

> **重复，本质上是渐进的迭代与递归。**
> 今天的你，站在昨天的你的肩膀上，再往前挪一寸。

这与 GitHub 贡献墙的视觉隐喻天然契合——**绿格子越连越长，情感拉力越强**。复利墙就是把这套叙事做成一个**纯前端、零依赖、打开即用**的工具：

- **对抗放弃冲动**是刚需（价值）
- **纯前端最稳**，交付确定性最高（可行性）
- **复利 / 长期主义**是笑来的思想主线（契合度）

相关观点出处：李笑来《把时间当作朋友》《通往财富自由之路》《七年就是一辈子》中关于「践行」「复利」「活在未来」「最少必要知识」的论述。

## 二、功能

| 功能 | 说明 |
| --- | --- |
| **每日打卡** | 记录任意可重复行为（阅读页数 / 朗读分钟 / 写作字数）。一条记录 = 数值 + 单位 + 一句「比昨天进步了什么」（递归视角的微进步标注）。 |
| **贡献热力墙** | GitHub 风格 53 周 × 7 天绿格子，深浅按当日**相对强度**分级（四分位），hover 显示当日数值与那句进步备注。 |
| **连续天数计数器** | 当前连续 streak + 历史最长 streak。断签后历史**不归零**，永久保留最佳记录。**数值大于 0 才算打卡**（见下方「打卡规则」）。 |
| **累计复利曲线** | 原生 Canvas 绘制累计增长曲线，可一键切换**「线性视角 vs 复利视角」**对比同一份积累的两种叙事。 |
| **多习惯支持** | 可建多个习惯（读书 / 英语 / 写作），各自独立的热力墙与曲线，标签色区分。 |
| **里程碑庆祝** | 连续到达 **7 / 30 / 100 / 365** 天时弹出庆祝卡。动画克制——格子轻微涟漪，而非彩带金币。 |
| **数据导出** | 导出 JSON 全量备份；用内置 html2canvas 把当前墙导出为 **PNG 分享海报**。 |
| **数据导入** | 粘贴 JSON 或上传备份文件恢复全部数据。 |
| **深浅色 + 响应式** | 跟随系统 / 浅 / 深三态切换；桌面与手机自适应。 |
| **存储兜底** | 优先写入完整 localStorage 快照；配额写入失败时等待 IndexedDB 提交，失败则保留表单并提示未保存。 |

## 三、页面

- **主面板 Dashboard** — 顶部 streak 卡片组 + 当前习惯热力墙 + 复利曲线。
- **今日打卡（模态）** — 数值输入 + 微进步文本框 + 保存。点击任意历史格子可补卡 / 编辑。
- **习惯管理** — 新增 / 编辑 / 删除习惯，设置名称、单位、标签色。
- **分享导出** — 预览海报样式 + 导出 PNG / JSON + 导入恢复。
- **理念页** — 「重复 = 渐进的迭代与递归」与复利叙事的极简文案。

## 四、如何使用

### 直接打开

双击 `index.html` 即可在浏览器运行——**无需后端、无需构建、无需安装任何依赖**。

> 小提示：本项目使用经典 `<script src>` 按依赖顺序加载（不是 ES Modules），
> 所以直接双击 `file://` 打开即可运行，不需要本地服务器。
> 如果你仍想用静态服务器，也可以这样起：
>
> ```bash
> cd compound-wall
> python3 -m http.server 8080
> # 然后浏览器打开 http://localhost:8080
> ```

### 打卡规则

- **数值大于 0 才算打卡。** 填 0 不会延续连续天数，也不计入「历史最长」和「累计打卡」天数；打卡输入框最小值为 0.01，填 0 会被浏览器拦下并提示。
- 旧版本留下的 0 值记录**不会被删除**，仍可在热力墙上点开查看或编辑，只是不再计入连续天数和累计天数。
- 「历史最长」另存了一份历史峰值（`meta.longestByHabit`）。旧版本曾因 0 值抬高过的峰值不会自动回退。

### 日常使用

1. 首次打开会自动创建一个「读书（页）」示例习惯。
2. 点击 **＋ 今日打卡**，填入今天的数值（必须大于 0），写一句「比昨天进步了什么」，保存。
3. 墙上对应格子点亮，连续天数 +1。坚持下去，绿色会越来越深、越来越连。
4. 在 **习惯** 页可以新建你自己的习惯（朗读 / 写作 / 跑步……）。
5. 在 **分享** 页导出 JSON 备份，或把墙导出成图，发给那个想放弃的自己。

## 五、技术与数据结构

- **Vanilla JS（经典 script，无构建）** + **原生 Canvas** 画曲线 + **CSS Grid** 画热力墙。
- **localStorage** 主存储，**IndexedDB** 兜底。
- 内联 vendored 的 **html2canvas**（单文件，不走 npm）。

### 文件结构

```
compound-wall/
├── index.html              入口，双击即跑
├── css/
│   └── styles.css          设计系统（暖橄榄绿 / 文人长期主义）
├── js/
│   ├── app.js              主控制器：视图、打卡、渲染、导入导出
│   ├── store.js            数据层：localStorage + IndexedDB 兜底
│   ├── stats.js            计算层：streak / 分级 / 曲线（纯函数）
│   ├── curve.js            原生 Canvas 曲线渲染
│   └── html2canvas.min.js  vendored 单文件，PNG 导出
├── tests/
│   ├── stats.test.cjs      stats.js 单元测试（node:test）
│   └── ui.cjs              浏览器端到端检查（Playwright）
└── README.md
```

### 测试

```bash
node --test tests/stats.test.cjs   # 计算层单元测试，无需浏览器
node tests/ui.cjs                  # 需要 Playwright 与 chrome-headless-shell
```

`tests/ui.cjs` 默认使用 `~/.local/bin/chrome-headless-shell`，可用环境变量 `CHROME_HEADLESS_SHELL` 指定其他无头浏览器路径。

### 旧版 localStorage 数据模型（保留用于恢复）

```jsonc
// cw:habits —— 习惯列表
[{ "id": "h_xxx", "name": "读书", "unit": "页", "color": "#6b8e23", "createdAt": 1717..." }]

// cw:logs:{habitId} —— 该习惯的打卡，按日期字符串索引（O(1) 查表）
{
  "2026-06-05": { "value": 25, "note": "今天多读了3页", "ts": 1717... }
}

// cw:meta —— 元信息
{ "longestStreak": 7, "lastExport": "2026-06-05T..." }

// cw:active —— 当前选中的习惯 id
"h_xxx"
```

导出格式为单一 JSON，合并所有上述 key：

```jsonc
{
  "app": "CompoundWall",
  "version": 1,
  "exportedAt": "2026-06-05T...",
  "habits": [ ... ],
  "logs": { "h_xxx": { "2026-06-05": { ... } } },
  "meta": { "longestStreak": 7, "lastExport": "..." }
}
```

## 六、设计说明

- **暖橄榄绿色温**：参考 GitHub 贡献墙的分级隐喻，但去掉蓝灰冷感，改用暖橄榄绿 `#6b8e23` → 深苔绿渐层。
- **文人长期主义气质**：衬线标题（Source Serif 4 / Noto Serif SC）+ 无衬线正文，暖白纸面 `#faf8f3`，极细纸纹底噪，无大圆角、无浮夸阴影。
- **克制的庆祝**：里程碑用「涟漪」而非彩带——像一本安静的修行日志，而非游戏化打卡 App。刻意避开通用 SaaS 蓝紫渐变。

## 七、隐私

所有数据**只存在你自己的浏览器里**，不上传任何服务器。换设备或清缓存前，记得在「分享」页导出 JSON 备份。

### 2026-09-16 存储升级

新写入使用 `cw:snapshot:v2` 完整快照（habits、logs、meta、active、revision）。仅在持久化提交成功后更新界面状态。初始化检查两种后端并选择较新快照；读取失败或副本冲突时进入只读，保留可读取的原始副本，不自动覆盖。旧版键不删除。

只读模式导出的是 `CompoundWall-Recovery` 诊断包，包含可读取原文和读取错误，不是可直接导入的普通备份。需要先判断哪份数据有效，再整理成正常备份。升级后请关闭或刷新旧标签页，避免旧页面继续向旧版键写入。支持 Web Locks 时串行处理跨标签写入；不支持该 API 的浏览器只保证本页串行。

本轮实际 Chrome 验证覆盖配额回退/刷新、事务中止、跨标签并发、损坏 schema 和读取失败恢复；尚未宣称所有浏览器、全部视觉 token 或完整产品验收通过。
