# SPEC · 44 串并联统筹板

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:一天要做十几件事的自由职业者、教师、小店主;付款人:本人。

## 核心任务(必须跑通)

1. 任务录入:名称、耗时(分钟)、类型(需要我在场 / 可以放着跑,如烧水、跑测试、等回复)、前置任务(多选)、最早开始时间(可选)。
2. 自动排程:拓扑排序 + 「放着跑」任务与「在场」任务并联;输出一条时间线(甘特:运行时 div 宽度 = 耗时);显示串联总时长 vs 统筹后总时长,节省百分比。
3. 循环依赖检测:有环 → 阻断并指出环上任务;前置不存在 → 阻断。
4. 手动上下移动调整顺序(按钮即可,不要求鼠标拖拽),违反前置时提示并拒绝。
5. 「再多想一步」提示(规则):某任务耗时 > 总时长 30% 且可拆 → 提示「考虑拆成两段」;连续 3 个「在场」任务 > 90 分钟 → 提示「插入放着跑任务或休息」。
6. 模板:保存今天的排程为模板,明天载入;导出甘特 SVG、任务 CSV、JSON;导入校验。

## 不做

不接日历、不做提醒、不估算真实耗时。

## core.js 暴露

`topoSort(tasks)` → `{order}` 或 `{cycle:[...]}`;`schedule(tasks)` → `{slots:[{id,start,end,lane}], total, serialTotal, saved}`;`validateOrder(tasks, order)`;`hints(schedule)`;`toSvg`;`toCsv`;`validateImport`。时间单位分钟整数。

## 示例

合成「上午 8 件事」:烧水 5(放着跑)、泡茶 2(前置烧水)、回邮件 20、跑测试 15(放着跑)、看测试结果 10(前置跑测试)、备课 40、打印 5(放着跑,前置备课)、打电话 10;标注「合成示例」。

## 测试点(≥ 12)

topoSort 正确顺序;环检测给出环成员;前置不存在拒绝;schedule 并联缩短(示例 saved > 0);放着跑任务不占在场 lane;串联总和正确;最早开始时间约束;validateOrder 违反前置返回原因;hints 两条规则各一例;toSvg 元素数 = 任务数;CSV 公式防护;validateImport 拒绝耗时非正整数;写读校验同源。

## 视觉方向

白 + 橙色「放着跑」/ 深灰「在场」两条泳道;手机端泳道纵向堆叠不横向滚动。

## 已知限制(写进 README)

只有两条泳道(在场/放着跑);不处理多人协作。
