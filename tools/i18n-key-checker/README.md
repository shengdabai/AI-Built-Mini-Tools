# 多语言文案键核对

## 定位
把各语言的文案文件放在一起,选一个源语言,一次查出缺键、多键、空值、占位符和 HTML 标签不一致,再生成待翻译表,译完合并回去并导出各语言 JSON。

## 目标用户
做多语言界面的独立开发者、小团队前端;付款人假设为技术负责人。

## 如何打开
双击 `index.html`(file:// 即可,无需安装、无需联网)。点页头「载入示例」看完整流程(示例是合成数据,已有数据时会先在页内确认再替换)。

## 核心任务
1. 导入:嵌套 JSON、扁平 `a.b.c` JSON、`.properties`、CSV(`key, zh, en, …`,每个语言列成为一份文件);可粘贴(填语言代码)或多选文件(语言从文件名推断,如 `en.json`、`messages_ja.properties`)。不合法的文件整份拒绝并说明原因。
2. 核对,每条带键名、语言、级别:
   - 阻断:缺键、多键、值为空(含纯空白)、占位符集合不一致(`{name}` `{{count}}` `%s` `%1$d` `$t(...)`)、HTML 标签集合不一致、文件没有任何键。
   - 警告:与源相同(可配「允许相同」键,支持 `*` 通配)、长度比 > 3 或 < 0.3、键名不符合约定(可配正则)、复数形式不完整、同源文本在不同键下译法不同。
3. 统计:每种语言的覆盖率、未译率、缺键/多键/空值/阻断/警告数,整体进度条;键矩阵按键和语言展开,手机上按语言分段。
4. 修复辅助:待翻译表 CSV(`key, source:<源语言>, 各目标语言空列`);译完预览后合并,默认只填空值和缺键,不覆盖已有值,可选覆盖;新键按源语言顺序插入。
5. 导出:核对报告 Markdown / CSV;合并后的各语言 JSON(保持嵌套结构与键顺序);待翻译表。

## 口径(SPEC 未规定,本实现的选择)
- 覆盖率与未译率的分母都是源语言的键数,两者不是互补关系:译文非空但与源相同的键,同时计入覆盖率和未译率(界面「整体进度」旁有同样的口径说明)。
- 覆盖率 = 源语言的键中,该语言有非空值的比例(复数组已有任一非空形式视为覆盖)。未译率 = 缺键 + 空值 + 疑似未译(与源相同且未被允许)的源键占比。整体 = 所有目标语言合计。
- 长度比 = 译文显示宽度 ÷ 源文本显示宽度;CJK、假名、谚文、全角字符算 2,其余算 1(否则中文源对拉丁语系几乎每条都超 3 倍)。不设最短长度限制,短词如「确定 / OK」可能误报,可用「允许相同」之外的方式忽略。
- 占位符与 HTML 标签按集合比较,不比较出现次数和顺序;ICU 复数语法 `{n, plural, ...}` 不解析。`%` 后跟 `sdfiuxXeEgGcb@` 才算占位符,`%%` 忽略。
- 默认键名约定:每段以小写字母或数字开头,其余为字母数字下划线,段间用点(`^[a-z0-9][A-Za-z0-9_]*(\.[a-z0-9][A-Za-z0-9_]*)*$`);kebab-case 会被警告,可改正则。
- 复数:`base_one/_other` 或 `base.one/.other` 等;某个文件里出现 `_other`、`.other` 或 `_one` 才把该 base 视为复数组(避免把 `step.one` 误判)。各语言所需类别用简化表(en/de/fr/es 等 one+other,ru/uk/pl 为 one/few/many/other,ar 六类,ja/zh/ko 等只要 other,未列语言只要 other)。缺键、覆盖率按实际键计算,复数集合警告另算;只有「该语言不需要的复数形式」缺失(如日语缺 `_one`)才不报缺键、视为不适用,目标语言需要的形式(如英语的 `_one`)多出源没有的键也不算多键。
- 同源异译:源语言中文本完全相同(去首尾空白)的 ≥ 2 个键,在某目标语言下出现 ≥ 2 种不同译文时报一条,列出相关键。
- 「与源相同」包括纯占位符、数字等本就不该翻译的文本,请用「允许相同」键模式豁免。
- CSV 里目标语言单元格为空 = 该键存在但值为空(报「值为空」)。
- 待翻译表默认只含缺键和空值的键;勾选后包含疑似未译。合并时用于防公式注入的前缀 `'` 会被还原。
- 嵌套 JSON 必须能无损还原:键名含点号与嵌套对象混用(如 `{"a.b":"x","c":{"d":"y"}}`)整份拒绝;纯扁平和纯嵌套导出文本与原文件结构一致。
- 导入拒绝而不是修正:JSON 叶子必须是字符串(数字 / 布尔 / null / 空对象 / 空数组都拒绝);同一文件内键重复、语言代码重复、CSV 列数不齐、引号未闭合或未引用字段里出现裸双引号都整份拒绝。

## 数据与安全
- 状态存 localStorage,键 `i18nkeys.v1`;保存前与读取后使用同一个 `validateState`。写入失败时页面顶部持续显示「未保存」并引导导出备份 JSON。
- 导出 CSV / Markdown 对以 `=`、`+`、`-`、`@`(及制表符、回车)开头的字段加单引号前缀(单独的 `-` / `+` 不算);Markdown 表格还转义 `|`、`<`、`>` 和换行。
- 键值表用有序数组而非普通对象,`__proto__`、`constructor` 作为键名安全。用户内容一律 textContent 渲染。

## 文件
`core.js` 纯逻辑(`detectFormat`、`parseJson`、`flatten`、`unflatten`、`parseProperties`、`parseCsv`、`placeholders`、`check`、`todoTable`、`merge`、`toJson`、`toCsv`、`reportToMarkdown` 等),`app.js` 界面,`sample-data.js` 合成示例,`styles.css`(顶部 `:root` 为设计 token,断点登记在 TOKENS 注释),`tests/core.test.cjs`,`shots.cjs`,`showcase.html/png`。

## 已知限制
- 不支持 `.po` / `.xliff`;不翻译、不读代码里的键引用。
- 嵌套 JSON 中的数组按索引键(`a.0`、`a.1`)处理,导出时变成带 `"0"`、`"1"` 键的对象,不还原为数组;数字样式的键名在 JS 对象里会被引擎重排,无法保持原顺序。
- 键名本身含 `.` 的嵌套 JSON(如 `{"a.b": ...}`)会与路径混淆;导出嵌套时出现键冲突(如同时有 `a` 和 `a.b`)会报错,需改用扁平。
- 导出 JSON / CSV 为 UTF-8;`.properties` 只导入,不导出。
- 键矩阵与问题列表每页显示 200 条,需点「显示更多」。
- 浏览器清除站点数据会丢失状态,请定期导出备份。
