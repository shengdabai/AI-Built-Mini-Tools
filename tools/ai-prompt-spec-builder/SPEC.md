# SPEC · 36 AI 提问规格生成器

目标用户:所有用 AI 干活的人。付款人:本人。

## 核心任务(必须跑通)

1. 表单(分步):① 任务一句话(谁、要什么、给谁用);② 限定条件(列表:范围、禁止项、格式、长度、语言、受众、已知事实、已有材料);③ 验收标准(列表:每条可观察,带「如何检验」);④ 输出结构(可选:标题/字段/示例);⑤ 角色与语气(可选)。
2. 质量检查(规则):任务句缺「给谁用」→ 提示;验收标准为空或含「好、优秀、专业」等不可观察词 → 警告并给改写示例;限定条件与验收冲突(同一关键词既在禁止又在要求)→ 提示;总字数 > 1500 → 建议精简。
3. 生成:按固定模板拼成完整提示词(分节:任务 / 限定 / 验收 / 输出格式 / 交付前自检清单);附「第一轮先问」版本:只发 ① 并要求 AI 先列限定条件与验收标准(对应李笑来三步法的第 1、2 步);一键复制。
4. 库:保存多个规格,标签、搜索;「从模板新建」(内置 6 个领域模板:调研、写稿、代码评审、数据分析、翻译、学习计划,内容为通用结构,无具体领域结论)。
5. 导出:提示词 Markdown;规格 JSON;全部规格 CSV。

## 不做

不调用模型、不评价答案、不做提示词「优化」玄学。

## core.js 暴露

`validateSpec(spec)` → `{issues}`;`vagueWords(text)`;`conflicts(constraints, criteria)`;`buildPrompt(spec)`;`buildFirstRound(spec)`;`templates()`;`search(specs, q)`;`toMarkdown`;`toCsv`;`validateImport`。

## 示例

合成 4 份规格(一份故意用「专业、高质量」等模糊词、一份有冲突、一份完整);标注「合成示例」。

## 测试点(≥ 12)

任务句检查;模糊词检测(可配词表);冲突检测;长度建议;buildPrompt 分节与顺序;buildFirstRound 只含任务;模板数量与结构;search;CSV 公式防护;validateImport;空规格;特殊字符不破坏 Markdown。

## 视觉方向

表单向导感:白 + 深蓝绿;分步进度条(div 宽度=运行时数据);手机端单列。

## 已知限制(写进 README)

模板是结构不是答案;提示词质量仍取决于你写的限定与验收。
