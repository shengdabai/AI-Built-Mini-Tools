# SPEC · 08 字幕术语校对

目标用户:做视频字幕的个人创作者与小团队(含做教学视频的教师)。付款人:创作者或内容团队负责人。

## 核心任务(必须跑通)

1. 粘贴或选择 SRT / WebVTT 文件(自写解析器:时间轴 `00:01:02,500 --> 00:01:04,000`(SRT 用逗号,VTT 用点)、多行文本、空行分隔;VTT 的 `WEBVTT` 头与 NOTE 块跳过;解析错误定位到行号)。
2. 术语表:每行 `标准写法 | 错误写法1, 错误写法2`(也认全角 `｜`、全角逗号);也支持只写标准写法(此时检查大小写 / 全半角变体:如 `GitHub` vs `github`、`Github`;中文词无变体检查)。选项:大小写敏感(默认否)。
3. 检查项(每条带 cue 时间、原文、建议):
   - 术语:命中错误写法;标准写法的大小写变体。
   - 时间轴:开始 ≥ 结束;与下一条重叠;时长 < 0.7 秒;时长 > 7 秒;CPS(每秒字符数,中文按 1 字 1 字符)> 阈值(默认 20);单行字数 > 阈值(默认中文 20 / 其他 42);超过 2 行;序号不连续;空文本。
4. 替换预览:对术语问题逐条「接受 / 跳过」,或一键接受全部;替换只改文本层,时间轴与序号原样保留(测试必须验证)。
5. 导出:修正后的 SRT(与输入同格式;VTT 输入导出 VTT);问题报告 Markdown / CSV。

## 不做

不做翻译、不做语音识别、不做时间轴自动调整(只报不改)。

## core.js 暴露

`parseSubtitles(text)` → `{format:'srt'|'vtt', cues:[{index, start, end, lines, raw}], errors}`;`parseGlossary(text)`;`checkTerms(cues, glossary, options)`;`checkTiming(cues, options)`;`applyFixes(cues, accepted)`;`serialize(cues, format)`;`cps(cue)`;`toMarkdown(issues)`;`toCsv(issues)`。时间用毫秒整数计算,序列化回原格式时毫秒补零。

## 示例

合成:一段 14 条中英混排教学视频字幕(SRT),刻意含:术语变体(`Github`/`github`)、错误写法(`拼音` 写成 `拼因`)、一处重叠、一处 0.4 秒、一处 CPS 超标、一处三行;术语表 5 条;标注「合成示例」。

## 测试点(≥ 14)

SRT 解析(多行文本、空行、Windows 换行 `\r\n`);VTT 解析(头、NOTE、点号毫秒);非法时间轴报行号;术语错误写法命中;大小写变体(默认不敏感命中,敏感时不命中);全角竖线与逗号;重叠;时长过短/过长;CPS 计算(中英文);行数与单行字数;序号不连续;applyFixes 不改时间轴与序号;serialize 往返(parse → serialize → parse 相等);公式防护。

## 视觉方向

剪辑软件感:深色主题(深炭灰底、浅字,AA),时间码用 `tabular-nums`;问题列表与字幕预览左右两栏;手机端上下堆叠。

## 已知限制(写进 README)

不支持 ASS/SSA;CPS 与行长阈值是通用建议,不是平台规范;术语检查按字面匹配,不做分词。
