# 定投复利践行账本

## 定位
用「固定规则 + 长期」做任何定投式践行(投资定投、每日写作、锻炼、阅读字数)的个人账本:记录是否按规则执行,缺勤自动对账,复利只按用户自己的假设做算术。不是投资工具。

## 目标用户
打算用固定规则长期践行的成年人(个人使用)。

## 核心任务
1. 新建践行:名称、类型(金额型/次数型/数量型)、固定规则(每天/每周 N 次/每月固定日)、每次定额、开始日期、可选止损规则文字(只记录,不执行)。
2. 记录:一键「按规则完成」或手填实际值;可补录过去日期;缺勤自动显示为「未执行」。
3. 复利视图:金额型给累计投入、按假设的账面值、投入线与假设线(内联 SVG)、同额一次性投入的算术对照;次数/数量型给连续、累计、执行率、按周热力条;「每天进步一点点」计算器含隔天对比。
4. 规则守卫:显示「本周还需执行 N 次」。**刻意没有「暂停」按钮**,只有页内确认的「结束践行」——用规则替代意志。
5. 导出:践行记录 CSV、月度总结 Markdown、JSON 备份与导入(非法文件整份拒绝并给原因)。导入入口(「导入 JSON 备份」)始终在页面顶部,空状态里还有「从 JSON 备份恢复」,首次打开的新设备可以直接恢复。

## 如何打开
双击 `index.html`(file:// 即可,无依赖、无联网)。加 `?today=2026-10-20` 可固定「今天」;格式非法时回退真实今天。数据存在浏览器 localStorage(键 `dcaledger.v1`);写入失败会出现持续可见的「未保存」横幅并引导导出。

## 功能与设计要点
- 三种规则的应执行次数:每周 N 次在本周只计「若要达标现在必须已做」的部分,首周按可用天数封顶;每月固定日遇短月取月末(含闰年);结束践行后不再计入应执行。
- 导出对以 = + - @ 开头的用户字段加单引号前缀;导入校验类型、枚举、日期、ID 与日期唯一性。
- 执行率 = 实际次数 ÷ 应执行次数,是真实比值(每周做多于定额时会超过 100%);应执行为 0 时显示「无应执行」。
- 金额型推算:每次定额是「每笔」金额。每周 N 次的践行,推算 K 周 = K×N 笔投入,复利按每年 52×N 笔滚动,一次性对照用同样的总额;曲线横轴为执行次数。
- 写入记录与导入/读取共用同一个校验函数(`validatePractice`),超限值(如大于 1e12)在写入前就被拒绝,不会出现「保存了但刷新后读不出来」。

## 口径
- 执行率 = 有记录的次数 ÷ 应执行次数。只要当天有一条大于 0 的记录就算执行一次,不看是否达到每次定额(定额 500 字、只写 1 字也算一次),所以它不表示完成定额的比例;热力条的颜色才区分「达到定额」和「低于定额」。
- 「未来新增投入的独立推算」只算从今天起按规则再坚持的新投入,不含已有记录的本金和增长,也不与「已发生的实际记录」相加。推算期数随规则显示为「推算天数 / 周数 / 月数」;每周 N 次时同时提示总执行次数(K 周 = K×N 次)。
- 今天已有记录时,「按规则完成」变为「查看/修改今日记录」,不会直接覆盖;用「记录这一天」改成不同的值时,先在记录旁确认新旧数值,取消则原值不变;写成相同的值不弹确认。
- 删除单条记录先在记录旁确认(写明日期),确认前连续天数、累计量、执行率都不变。
- 合成示例的标记持续可见(列表、详情标题);导出的 CSV 多一列「数据来源」(合成示例/真实数据),月度总结 Markdown 写明数据来源。
- 地址带合法 `?today=` 时页面顶部持续显示「基准日 …(由地址参数固定)」。
- 键盘:切换践行、记录、删除后焦点留在原位或相邻控件;校验失败时错误显示在出错输入旁(`aria-describedby`)并聚焦第一个出错输入。
- innerHTML 核对:app.js 里 innerHTML 模板中的用户文字(践行名称、单位、止损规则、导入错误信息)全部经 `esc()` 转义;其余插值为程序计算出的数字或固定枚举。

## 已知限制
- 不是投资工具:不接行情、不推荐标的、不给收益承诺;曲线完全由用户输入的年化假设决定。
- 不同设备数据不互通,换设备请用 JSON 备份。
- 复利按「期初投入、期末结算」的简化模型;实际账面值按天复利折算,均为算术对照。
- 结束践行后不能重启;不支持修改已创建践行的规则(需新建)。
- 示例数据全部为合成。
