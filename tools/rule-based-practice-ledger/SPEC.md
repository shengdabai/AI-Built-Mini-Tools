# SPEC · 12 定投复利践行账本

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:打算用「固定规则 + 长期」做任何定投式践行的成年人(投资定投、每日写作、每日锻炼、每日阅读字数)。付款人:个人。大市场。

## 核心任务(必须跑通)

1. 新建「践行」:名称、类型(金额型 / 次数型 / 数量型,如字数、分钟)、固定规则(每天 / 每周 N 次 / 每月固定日)、每次定额、开始日期、可选「止损规则」文字(只记录,不执行)。
2. 记录:每天一键「按规则完成」或手填实际值;可补录过去日期;缺勤自动显示为「未执行」。
3. 复利视图(全部确定性计算):
   - 金额型:输入年化假设(默认 0,可调,明确标注「假设,不是预测」),给「累计投入 / 按假设的账面值 / 两条曲线(投入线、假设线)」,并给「一次性投入同额对比」仅作算术对照。
   - 次数型/数量型:连续天数、累计量、执行率(实际次数 / 规则应执行次数)、按周热力条。
   - 「每天进步一点点」计算器:输入每日进步率(如 1%)和天数,算出 (1+r)^n,并与「隔天做」对比,直观展示规则稳定性的影响。
4. 规则守卫:显示「本周还需执行 N 次」;不提供「暂停」按钮,只有「结束践行」(页内确认),呼应「用规则替代意志」;README 解释这是刻意设计。
5. 导出:践行记录 CSV;月度总结 Markdown(执行率、连续天数、累计);JSON 备份导入。

## 不做

不接任何行情、不推荐标的、不给收益承诺;年化只是用户假设。

## core.js 暴露

`expectedCount(rule, start, today)`;`streak(records, rule, today)`;`executionRate(...)`;`compound(amountPerPeriod, periods, annualRate, periodsPerYear)` → 曲线数组;`growth(dailyRate, days)`;`weeklyHeat(records, today)`;`monthlySummary(records, rule, month)`;`toCsv`;`toMarkdown`;`validateImport`。

## 示例

合成 3 条践行:每日写作 500 字(数量型,开始 60 天前,有几天缺勤)、每周 3 次锻炼(次数型)、每月 1 日定投 1000(金额型,12 期,年化假设 0 与 6% 可切换);标注「合成示例,年化为假设」。

## 测试点(≥ 14)

expectedCount 三种规则含月末/闰月;streak 断裂与补录;executionRate 不除零;compound 在 0 年化等于累计投入、6% 时单调递增且期数正确;growth(0.01, 365) ≈ 37.78;隔天对比;weeklyHeat 7 列;monthlySummary 边界;结束践行后不再计入应执行;`?today`;导入拒绝非法类型;CSV 公式防护。

## 视觉方向

账本 + 长期主义感:深墨绿与米灰(不是奶油),曲线用 SVG(内联,token 色);手机端曲线可横滑。

## 已知限制(写进 README)

不是投资工具;曲线按用户假设;不同设备数据不互通。
