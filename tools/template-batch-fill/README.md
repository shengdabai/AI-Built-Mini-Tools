# 模板批量填充

写一份带 `{{字段}}` 的纯文本模板,粘贴一张 CSV/TSV 表,逐条预览,再批量输出成合并文本、zip 或 CSV。纯前端,数据只存在本机浏览器。

## 目标用户

教师(家长通知、评语)、小团队运营(邮件正文、合同抬头)、活动组织者(证书、名牌文字)。

## 核心任务

1. 模板:`{{字段}}`、`{{字段|默认值}}`、`{{#if 字段}}…{{/if}}`(只判断非空,不能嵌套)。独占一行的条件标签不留空行。
2. 数据:粘贴 CSV/TSV,首行为字段名,自动识别逗号、制表符、分号;支持引号内的分隔符与换行。列出「模板用到、数据没有」与「数据有、模板没用」的字段。
3. 预览:逐条渲染,上一条/下一条/下一条未填;空值且无默认值的占位符红色标出并计数。
4. 输出:合并文本(自定义分隔线)、zip(自写 store 模式,每条一个文件,文件名模板如 `{{姓名}}-通知.txt`,重名自动加序号)、渲染结果 CSV、JSON 备份。
5. 校验:占位符未闭合、条件块不配对或嵌套、非法字段名、表头重复、列数不等,均带行号。任一模板或数据解析错误(含 CSV 引号未闭合、重复表头、列数不等)都会阻断整批预览与生成,三种导出按钮同时禁用,必须先改对。示例数据里故意留了一行多一列,载入后先显示报错,删掉多出的一列才能输出。
6. 文件名模板同样检查:占位符未闭合,或用到数据里没有的字段,会在文件名输入框下方报错并只禁用 ZIP(合并文本和 CSV 不受影响);逐条为空的字段只提示(空的部分会被省略,全空时文件名为 untitled,重名自动加序号)。

## 如何打开

双击 `index.html`。无需安装、无需联网。第一步:点「载入合成示例」(虚构的家长通知与 12 行学生数据,含缺字段行、多一列的行、半数为空的条件字段)。示例的第 12 行是**预设的错误**(多了一列),用来演示报错:检查面板会明确写出这一点,并提供「定位到数据第 12 行」和「移除多出的末尾列并继续」两个按钮,点后即可预览和输出。

## 文件

`core.js` 纯逻辑;`app.js` 界面;`styles.css` 顶部为 token;`tests/core.test.cjs` 单元测试;`shots.cjs` 真实操作界面的截图与断言脚本。

## 保存与替换

- 保存与读取共用同一个校验(`validateImport`):只查类型与大小,允许有语法错误的半成品模板;模板超过 200000 字符或数据超过 2000000 字符时,保存前拒绝并显示持续提示,localStorage 里保留上次保存的内容,刷新后回到那一份。
- 如果 `tplfill.v1` 不是合法 JSON,或字段类型不符合备份格式,页面会原子拒绝整份存档,不会部分载入。页面持续显示恢复提示,并允许逐字下载损坏原文。
- 用户第一次修改后,页面会先把损坏原文写入独立的 `tplfill.v1.corrupt.<时间>` 键,再读回逐字核对。归档键已存在时会增加唯一后缀,不会覆盖旧归档。每次准备覆盖主键前都会重新核对归档;归档被清除时会重新建立。只有核对一致后才写主键。归档、读回或主键写入失败时,旧主键不变;当前有效内容只在内存里,页面会明确要求导出恢复 JSON。
- 恢复 JSON 只包含当前页面内存里的 `template`、`data`、`filePattern`、`separator` 和 `sample`;文件内有 `recoveryScope` 与 `recoveryNote`,不会把损坏原文或浏览器中的其他数据说成已包含。
- 如果本次页面连旧主键都无法安全读取,本次页面生命周期内会封锁所有浏览器存储写入。输入、导入和清空只能改变内存状态,不会覆盖或清除内容未知的旧主键;导出当前内存 JSON 后刷新页面才能重新尝试读取。
- 载入示例、导入 JSON 备份、清空前的确认判据:模板、数据、偏离默认的文件名模板、偏离默认的分隔线;确认文案列出被替换的项目。导入备份走「校验 → 预览模板字数与数据行数 → 确认 → 写入」;确认前不改内容也不写存储。
- 导入入口(JSON 备份)在页头和空状态引导里始终可见。

## 口径
- 「条」= 数据里除表头外的每一行,一条输出一个文件;「未填」= 模板里没有值也没有默认值的占位符个数(同一字段出现几次算几处,条件块没输出的部分不计)。
- 检查结论:模板、数据、文件名模板任一处有错,写「检查未完成:N 处错误」并停用预览和相应输出;三者都通过才写「都没有发现错误」。
- 示例标记(`sample`)随数据保存,刷新后仍在;改动模板或数据、清空、导入不带标记的备份后消失。导出的 CSV 多一列「数据来源」、JSON 备份带 `sample:true`;ZIP 与合并文本是模板输出本身,不改内容,只在文件名前加「合成示例-」。
- 错误同时显示在出错的输入框下方(模板、数据、文件名模板,`aria-describedby` 关联),检查面板做汇总。
- 「移除多出的末尾列」只处理列数多于表头的行,删掉表头之外的末尾单元格;数据会按识别出的分隔符重新整理格式(需要时加引号),内容不变。
- 安全核对(2026-10-20):`app.js` 全部用 `textContent` / `createElement` 渲染,没有 `innerHTML` 拼接。

## 已知限制

- 不做富文本、不发邮件、不生成 PDF 或图片、不支持循环语法。
- 条件块只判断「非空」,不能嵌套。
- zip 不压缩(store 模式);zip 内文件名为 UTF-8,个别老旧解压工具可能显示乱码。
- 大数据量(数千行以上)时每次输入都会整体重算,可能变慢。
- 数据按单元格首尾去空白处理。
- 没有「跳过异常行」选项:有任何数据解析错误就不生成,需要先改数据。
