# 库存异常检查

## 定位
贴入库存表,逐行核对「期初 + 入库 − 出库 = 期末」,并找出负库存、重复编码、单位混用、低于安全库存等异常,每条异常带原表行号。

## 目标用户
自己管库存表的小型零售运营、店主(付款人:店主)。

## 核心任务
1. 导入 CSV/TSV/粘贴,自动匹配列(商品编码必选;商品名、期初、入库、出库、期末、单位、安全库存、单价可选)。
2. 标准化数字(千分位、全角、空值按 0 并警告)与单位(同义表可编辑,只归一不换算)。
3. 12 条规则:阻断 5 条(期末不等、期末为负、编码重复、编码为空、数字非法),警告 7 条(同编码单位不一致、低于安全库存、期末为 0 但有入库、先出后入、名称相同编码不同、单价为空但有出库、空值按 0)。
4. 汇总:行数、异常数、各规则命中数、按单位分组的期末合计、库存金额。
5. 修复辅助:显示「按公式应为 X」;「采用公式期末」只改选中行。
6. 导出:异常清单 CSV / Markdown(含原行号)、修正后库存表 CSV。

## 如何打开
双击 `index.html`。无需安装、无需联网。数据只存在本机浏览器 localStorage(键 `invcheck.v1`);写入失败时页面顶部持续显示「未保存」并引导导出。

## 口径
- 数据行数 = 表头以下的非空行;「有异常的行」按行计,一行可命中多条规则;阻断条数、警告条数、各规则命中数按命中条数计,所以条数可以大于行数。
- 库存金额 = 期末 × 单价,只统计期末非负且单价有效的行;币种取自「金额币种标注」(只做标注、不换算),留空时写「原表统一货币单位」。单价列里所有数字必须是同一种币种。
- 「没有发现问题」只在检查完整完成时出现:所有 12 条规则都有对应列并已运行、且没有解析错误。缺列时写「检查未完成」并列出没运行的规则;解析失败时写「检查未完成:1 处错误」,原因持续显示在输入框下方,直到下一次解析成功才清除。
- 载入示例、导入文件、清空、重新解析前,页内确认会写明被替换的内容:库存数据行数、已采用的公式期末行数、输入框里还没解析的字符数、改过的列映射、单位同义表、币种标注。
- 示例标记「合成示例数据」刷新后仍在;导出的异常清单 CSV / Markdown 和修正后库存表 CSV 都带「数据来源=合成示例」;重新解析自己的表、导入文件或清空后消失。
- 输入框改动后,下面显示的是上一次检查的结果,导出暂停,重新解析后恢复。
- 安全核对(2026-10-20):`app.js` 全部用 `textContent` / `createElement` 渲染,没有 `innerHTML` 拼接。
- 本产品没有 JSON 备份和单条删除:要保留的只有库存表,所以保存失败时导出「当前内存里的全部修正后库存表 CSV」,再用「选择 CSV 或 TSV 文件导入」读回。

## 已知限制
- 不处理多仓。
- 单位只归一不换算;未知单位原样保留。
- 规则只核对表内数字,不替代实物盘点;不做预测。
- 「采用公式期末」后若要恢复原值,需重新点「解析并检查」或改列映射(会重新读取原表)。
- 单独的 `-` 视为空值;`1,2` 这类不规范千分位视为非法数字。
- 金额只统计期末非负且单价有效的行。
- 引号未闭合的表格整份拒绝,不会进入检查和保存。
- 零容差按输入的十进制精度精确比较(不经过浮点数),连 0.0000001 的差异也会报。
- 导入的 CSV 以逗号/制表符/分号分隔,按 UTF-8 读取。
- 币种只是标注,工具不识别也不换算币种;单价列混用币种时金额没有意义。
