# SPEC · 26 链接参数预检

目标用户:运营、投放、内容发布者。付款人:运营负责人。

## 核心任务(必须跑通)

1. 粘贴一批链接(每行一条,或 CSV 列);解析 URL(自写容错:无协议补 `https://` 并警告;非法 URL 阻断)。
2. 规则(每条带行号、级别):
   - 阻断:无法解析;协议非 http(s);UTM 必填项缺失(默认 `utm_source, utm_medium, utm_campaign`,可配);同一参数重复出现且值不同;参数值含未编码空格或中文(给编码后值);
   - 警告:大小写混用(`utm_Source`);值含大写(约定小写,可关);`utm_campaign` 命名不符合用户规则(可配正则,默认 `^[a-z0-9_-]+$`);链接含片段 `#` 且在参数后;重复链接;域名不在允许列表(可配);参数顺序不一致(同一域名下);
3. 规范化:按规则生成「建议链接」(小写键、编码值、去重、按字母排序参数,保留非 UTM 参数原样);一键采用。
4. 批量构建:给定基础链接 + 参数表(CSV:`source, medium, campaign, content, term`),生成全部组合链接。
5. 导出:检查结果 CSV/Markdown;规范化链接列表;构建结果 CSV。

## 不做

不访问链接、不缩短链接、不查点击数据。

## core.js 暴露

`parseUrl(text)`;`check(urls, options)` → `{issues, stats}`;`normalize(url, options)`;`build(base, rows, options)`;`parseBatch(text)`;`toCsv`;`issuesToMarkdown`。URL 解析可用 `URL` 构造函数(Node 与浏览器都有),但要处理抛错。

## 示例

合成 16 条链接:缺 source、重复参数不同值、未编码中文、大小写混用、片段位置错、非 https、重复链接、域名不在列表;参数表 3×2;标注「合成示例」。

## 测试点(≥ 12)

无协议补全;非法 URL;必填缺失(可配);重复参数;编码检测与编码后值;大小写;campaign 正则;片段位置;重复链接;域名列表;normalize 幂等;build 组合数;CSV 公式防护;空输入。

## 视觉方向

投放工具感:白 + 深蓝;链接等宽显示(仅链接本身);手机端卡片。

## 已知限制(写进 README)

规则按常见约定,不替代各平台的实际要求;不做短链。
