# 跨时区课表核对

## 定位
把教师自己时区的每周固定课表,对照成每位学员的本地时间,并提前标出夏令时切换周。

## 目标用户
教海外学员的线上教师、跨时区协作的自由职业者。付款人:本人。

## 核心任务
1. 维护学员与 IANA 时区(下拉用 `Intl.supportedValuesOf('timeZone')`,并入常用别名;不可用时回退内置 60 个常用时区)。
2. 录入每周固定课表(教师本地时区),支持某日取消或改时间的例外。
3. 选一周生成对照表,每节课显示教师与学员本地时间,跨日标「次日/前一日」。
4. 夏令时提醒:对比上周到本周、本周到下周同一课的学员本地时间,变化则标「切换周」;另列未来 60 天的切换日期。
5. 导出:Markdown(每人一段)、ICS(教师时区,带 TZID)、JSON 备份与导入。

## 如何打开
双击 `index.html`(file://,无需联网)。演示用 `index.html?today=2026-10-26` 固定今天;日期格式非法时回退真实今天。点「载入示例」可看合成数据。

## 功能说明
- 数据存浏览器 localStorage(键 `tzcheck.v1`)。写入失败时页面顶部持续显示「未保存」提示,请导出 JSON 备份。
- 生成对照表后若再改动课表或所选周,结果标为过期,Markdown 与 ICS 导出禁用,重新生成后恢复。
- 导入 JSON 会整份校验(时区、枚举、ID 只允许字母数字 - _ 且唯一、引用、同一课节同一天至多一个例外),不合法就整份拒绝并说明原因。
- ICS 输出对 UID/TZID 只保留安全字符,SUMMARY 按 RFC 5545 转义换行、逗号、分号、反斜杠;课节结束时间在 UTC 时间轴上加时长再转回时区,跨夏令时切换也正确。
- 不存在的本地时间(春季空洞,如柏林 03-29 02:30)统一顺延为 03:30。
- Markdown 表格里以 `=`、`+`、`-`、`@` 开头的用户字段加单引号前缀。

- 删除学员、课节、例外都先在页内确认:学员确认写明连带删除的课节与例外数,课节确认写明连带删除的例外数;确认前数据不变。
- 「编辑」学员可改姓名与时区,保留学员 ID 与关联课节、例外;改动后已有的对照结果标为过期,需重新生成,编辑中 Markdown/ICS 导出禁用。
- 页面持续显示「基准日 YYYY-MM-DD」:地址带合法 `?today=` 时写明「由地址参数固定」。示例不再固定日期;载入示例后出现「查看 2026-10-26 所在周」按钮,用于演示夏令时切换。
- 载入合成示例后,页面持续显示「合成示例」标记(按示例学员 ID 判断,刷新后仍在),清空或导入真实备份后消失。
- 载入示例、清空、导入 JSON 都先页内确认并写明替换/清空的学员、课节、例外数量(含未提交的姓名草稿);导入先校验再预览数量。

## 口径
- 周一为一周起点;所选周由所选日期所在周决定。
- 夏令时对比:同一课教师时间不变且未取消时,比较上周与本周、本周与下周的学员本地时间;被例外改时间的课不参与。
- 学员本地时间由教师时区的具体日期时间经 UTC 换算得到,不使用固定偏移;结果为空时会写明原因(没有课节、所选周没有课)。

## 已知限制
- 时区数据以浏览器内置 Intl 为准,不同浏览器版本可能有差异。
- ICS 只含教师时区的事件,且不含 VTIMEZONE 定义,依赖日历软件识别 IANA 的 TZID。
- 不处理历史时区规则变更;夏令时空洞时刻的课顺延空洞长度(02:30 变 03:30)。
- 不接日历 API,不发消息。
- 夏令时对比只在「同一课教师时间不变」且未取消时进行,被例外改时间的课不参与。
