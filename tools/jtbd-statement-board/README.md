# JTBD 任务陈述板

纯前端、双击 `index.html` 即用(file:// 可用,无依赖、无联网、无登录、无支付、无埋点)。

## 定位
在做方案之前,先把任务写成「当[情境],我想[动机],以便[期望结果]」,再用推力、拉力、惯性、焦虑四力检查。JTBD(Jobs To Be Done)指用户要完成的任务。

## 目标用户
做产品、做课程、做服务的人。付款人:本人。

## 核心任务
1. 任务陈述:三段句式 + 四力(每项一个列表)+ 当前替代方案(名称、费用、耗时、不满点)+ 使用者/购买者/触发时刻/成功的可观察结果。
2. 规则检查:句式留空 → 阻断(并禁用任务陈述卡导出);动机含方案词(词表可配,默认 APP、工具、功能、按钮)→ 警告;期望结果无可观察词 → 提示;推力+拉力 条数 ≤ 惯性+焦虑 条数 → 提示;没有替代方案 → 警告。
3. 候选对比:同一任务下多个候选,勾选各自解决的推力/拉力、缓解的焦虑,显示覆盖矩阵与覆盖数;不打总分、不排名。
4. 证据挂接:推力/拉力可挂证据(访谈/帖子/数据/自己猜,含来源与日期),无证据标「假设」,统计假设占比。
5. 导出:任务陈述卡 Markdown、覆盖矩阵 CSV、全部数据 JSON 备份;JSON 导入做整份校验。

## 如何打开
双击 `index.html`。地址后加 `?today=2026-10-20` 可固定「今天」(用于证据默认日期;非法或会自动进位的日期如 2026-02-30 回退真实今天)。

## 口径(SPEC 未规定,本实现的选择)
- 「假设」= 推力/拉力条目没有任何证据;只有「自己猜」证据的条目不算假设,但单独统计「只有自己猜」的条数。
- 空白文本的条目不计入条数、覆盖矩阵与统计。
- 可观察词:阿拉伯数字、「数字+单位」(如三天、两周)、时间词(秒/分钟/小时/每天/每周/以内/之前等)、「能」「不再」。
- 方案词匹配不区分大小写,词表按任务保存,用逗号、顿号或空格分隔。
- 惯性与焦虑不挂证据;证据来源若写成链接,只接受 http(s)(以 javascript:、data:、file: 等开头的整份拒绝)。
- 删除确认:删除四力条目(含它的证据、候选方案里的勾选)、证据、有内容的替代方案、有内容的候选方案,都先在页内确认;确认文案写明内容、证据数和受影响候选数,确认前数据不变。空白条目直接删除。
- 「导入 JSON 备份」在页面顶部和空状态引导里始终可见;空库导入直接生效,已有数据时先确认。
- 导入是整份替换(有数据时先页内确认),任一字段不合法整份拒绝并列出原因。
- 对文本长度、条数不设上限;存储空间满时显示持续可见的「未保存」提示。
- 导出 CSV/Markdown 表格里以 = + - @ 开头的字段加单引号前缀(单独的 - 或 + 不加)。

## 已知限制
- 框架帮助你问对问题,不替代访谈;证据类型「自己猜」必须诚实标注,工具只能统计,不能判断真假。
- 不联网找证据、不生成方案、不打分排序。
- 数据只存在本机浏览器 localStorage,换浏览器或清站点数据会丢失,请定期导出 JSON。
- 示例数据全部是合成示例。
- 不支持任务之间复制条目、证据附件和拖拽排序。
