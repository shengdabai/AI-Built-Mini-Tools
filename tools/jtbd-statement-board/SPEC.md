# SPEC · 40 JTBD 任务陈述板

目标用户:做产品、做课程、做服务的人。付款人:本人。

## 核心任务(必须跑通)

1. 任务陈述:固定句式填空「当 [情境],我想 [动机],以便 [期望结果]」+ 四力(推力:现状的不满;拉力:新方案的吸引;惯性:现状的习惯;焦虑:对新方案的担心),每项列表;当前替代方案(列表:名称、费用、耗时、不满点);使用者 / 购买者 / 触发时刻 / 成功的可观察结果。
2. 规则检查:三段句式任一为空 → 阻断;动机里出现产品名或功能词(用户可配词表,默认含「APP、工具、功能、按钮」)→ 警告「写的是方案不是任务」;期望结果不含可观察词(数字、时间、「能/不再」)→ 提示;推力 + 拉力 条数 ≤ 惯性 + 焦虑 条数 → 提示「切换阻力大于动力」;替代方案为空 → 警告「没有替代方案通常意味着没有需求或没调研」。
3. 候选对比:同一任务下多个候选方案,各填「解决了哪条推力/拉力」「缓解了哪条焦虑」,自动算覆盖数;不做总分排名,只显示覆盖矩阵。
4. 证据挂接:每条推力/拉力可挂证据(文本 + 来源 + 日期 + 类型:访谈/帖子/数据/自己猜),无证据的标「假设」;统计假设占比。
5. 导出:任务陈述卡 Markdown(一页);覆盖矩阵 CSV;JSON 备份;导入校验。

## 不做

不打分排序、不联网找证据、不生成方案。

## core.js 暴露

`validateJob(job)` → `{issues}`;`solutionWords(text, words)`;`observable(text)`;`forceBalance(job)`;`coverage(job, candidates)` → 矩阵;`evidenceStats(job)`;`toMarkdown`;`toCsv`;`validateImport`。

## 示例

合成 2 个任务:「课后给家长发反馈」(含 4 力各 2–3 条、2 个候选、部分有证据)、「每周整理读书笔记」(动机写成了方案,演示警告);标注「合成示例」。

## 测试点(≥ 12)

句式空检查;方案词检测(可配);可观察检测;力平衡提示;替代方案为空;coverage 矩阵与计数;evidenceStats 假设占比(除零);证据类型枚举;Markdown 一页结构;CSV 公式防护;validateImport;多任务独立。

## 视觉方向

工作坊白板感:浅灰 + 深蓝;四力两列对照;手机端纵向。

## 已知限制(写进 README)

框架帮助你问对问题,不替代访谈;证据类型「自己猜」必须诚实标注。
