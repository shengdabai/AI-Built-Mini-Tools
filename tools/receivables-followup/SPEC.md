# SPEC · 15 应收账款跟进清单

目标用户:服务企业财务、自由职业者。付款人:财务负责人或企业主。

## 核心任务(必须跑通)

1. 录入账单:客户、账单号、开票日、到期日、应收金额、币种、迁移前已收、争议备注、迁移前最近跟进。单条表单 + 批量粘贴(`客户 | 账单号 | 到期日 | 应收 | 已收`)+ CSV 导入(列映射)。迁移前字段是旧数据起点,不生成付款或联系事件。
2. 账龄(以 `?today` 或真实今天为基准日):余额 = 应收 − 已收;只对余额 > 0 的分组:未到期 / 逾期 1–30 / 31–60 / 61–90 / 90 天以上;汇总各组金额与笔数(按币种分开)。
3. 跟进清单:按逾期天数降序;「今天要跟」= 逾期且(从未跟进 或 距最近跟进 ≥ N 天,N 默认 7);每条生成提醒草稿(模板可改,占位符 `{客户}{账单号}{金额}{到期日}{逾期天数}`),一键复制;记录一次跟进(日期 + 备注),有争议的单独标记并排除出自动提醒。
4. 收款登记:给某账单加一笔已收(日期、金额)→ 余额重算;已收 > 应收 报错。
5. 导出:账龄表 Markdown/CSV;跟进清单 CSV;JSON 备份导入。

## 数据一致性

- `paid = openingPaid + sum(payments.amount)`。`lastFollow = max(openingLastFollow, follows.date)`。
- 编辑账单时 `paid` 和 `lastFollow` 是只读派生值。付款和跟进只能追加事件;补录较早跟进不能让最近跟进倒退。
- JSON v2 显式保存 `openingPaid` 和 `openingLastFollow`。v1 标量会迁移成显式起点;有部分历史时只保留非负金额差额和晚于历史的标量日期。
- v1 中收款合计大于已收汇总,或历史最晚跟进晚于最近跟进汇总,都属于矛盾。导入必须在改变现有数据前整份拒绝。
- 收款只接受正数。退款或冲销不使用负数事件。金额必须有限、最多两位小数且不超过 9,000,000,000,000.00；同币种账龄汇总也受此上限约束。整数分累计后再输出金额。超限报告与导出必须显式失败。

## 不做

不发邮件/消息;不接银行;不做利息/违约金计算。

## core.js 暴露

`balance(bill)`;`ageBucket(bill, today)`;`agingReport(bills, today)`;`followUpList(bills, today, n)`;`draft(template, bill, today)`;`addPayment(bill, payment)`;`parseBatch(text)`;`toCsv`;`toMarkdown`;`validateImport`。

## 示例

合成 10 条账单、3 个客户、两种币种,含:一条有争议、一条已结清、一条逾期 95 天、一条今天到期;标注「合成示例」。

## 测试点(≥ 12)

五个账龄桶的边界(到期日当天=未到期;逾期 30/31/60/61/90/91);余额 0 不入账龄;币种分组;今天要跟的两个条件;争议排除;draft 占位符替换与转义;addPayment 超额拒绝;parseBatch 全角分隔与错误行;CSV 公式防护;`?today`;validateImport。

## 视觉方向

账本感:深蓝 + 浅灰,账龄桶用五档由冷到暖的条;手机端卡片。
