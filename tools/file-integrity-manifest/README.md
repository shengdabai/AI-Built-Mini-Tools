# 文件完整校验

## 定位

交付或接收一批文件时的完整性校验工具:交付前给文件夹生成 SHA-256 清单,接收后导入清单,核对缺失、多出、被改动的文件。全部在浏览器本机计算,文件不上传。

## 目标用户

需要交付或接收一批文件的人(设计交付、课程资料包、客户资料)。设想的付款人是交付方。

## 核心任务

1. 生成清单:选择文件夹或拖入文件,读取相对路径、大小、修改时间,计算 SHA-256(显示进度),导出清单 JSON / CSV。
2. 核对清单:导入清单(JSON 或 CSV)+ 选择收到的文件夹,得出缺失、多出、哈希不一致、大小写差异、内部错误。
3. 规则:路径统一为 `/` 并做 NFC 规范化;默认忽略 `.DS_Store`、`Thumbs.db`、`__MACOSX/`(可编辑);文件名含 `<>:"|?*`、控制字符或单个文件名超过 255 字节时警告。
4. 汇总与筛选:文件数、总大小、各状态数;按状态与路径筛选。
5. 导出:核对报告 Markdown / CSV;清单 JSON / CSV。

## 如何打开

- 双击 `index.html`(纯前端,无依赖、无联网、无登录)。
- 「载入示例对比」不需要真实文件:15 条合成清单对一份合成文件列表(2 缺失、1 多出、1 哈希不一致、1 大小写差异、1 非法文件名、含 `.DS_Store`)。示例全部为**合成**,结果区带「合成示例」标识。
- 保存范围:忽略列表和「核对页当前清单」存在 localStorage(键 `filecheck.v1`),并记录该清单是否为合成示例。启动时先校验整个存档,只有全部字段和清单合法才一次性加载。「生成清单」页刚生成的清单只在内存里;点「用这份清单去核对」才把它存成当前清单。收到的文件(含哈希)从不保存。
- 存档损坏时,页面保留并可下载原始字符串。每次保存前,页面都重新回读恢复副本;副本被删除或改动时会重新归档。恢复键如果已存在,页面使用数字后缀,不覆盖旧副本。主键写入后也必须逐字回读一致才报告成功。读取失败会单独报错,不冒充「没有存档」。
- 存档读取失败时,「清空清单和忽略列表」也会被拦截。页面不调用 `removeItem`,也不修改当前内存状态。
- 写入失败时页面顶部持续显示「未保存」提示,并提供「导出当前有效状态 JSON」。该文件包含当前忽略列表和清单,可通过同一套存档校验往返读取。
- 地址加 `?today=2026-10-20` 可固定导出文件名与报告里的日期,页面顶部持续显示「基准日 YYYY-MM-DD(由地址参数固定)」;非法值回退真实今天且不显示。

## 功能说明

- 哈希:不超过 32MB 的文件用 Web Crypto 一次读入;更大的文件分块(4MB)读取,用 `core.js` 内的增量 SHA-256(与 `node:crypto` 对照测试一致),并显示进度。
- SHA-256 只能说明两次计算的内容是否一致。如果清单来源不可信,哈希不能证明文件来源或真实性。
- 所选文件夹自身的名字不计入路径,清单在文件夹改名后仍可使用。
- 大小写差异:清单有 `A.png`、实际只有 `a.png` 时,单列为「大小写差异」,不重复计入缺失和多出。
- 大小与哈希矛盾(哈希相同、大小不同)报「内部错误」。
- 导入清单严格校验:字段类型、sha256 格式、非负整数大小、日期、路径不含 `..`、路径不重复;任何一项不合法整份拒绝并给出原因。
- 导出的 CSV / Markdown 表格里,以 `=`、`+`、`-`、`@` 开头的字段加单引号前缀;原本就是若干个 `'` 后接这些字符的文件名再多加一个 `'`,导入 CSV 时去掉一个,所以往返可逆(`'=abc.txt` 导出为 `''=abc.txt`)。
- 大小写差异配对后仍做完整检查:哈希相同但大小不同时,除「大小写差异」外另报「内部错误」。
- 已有清单、收到的文件或偏离默认值的忽略列表时,点「载入示例对比」先在页内确认替换。
- 拖放区可用键盘:聚焦后按 Enter 或空格打开对应的文件选择器。
- 重新选择文件(或文件夹)开始读取的瞬间,旧结果和导出按钮立即作废,读取失败后也不会残留。
- 忽略列表或清单、收到的文件改动后,旧核对结果作废,导出按钮随结果一起隐藏,需重新核对。

## 口径

- 「清单文件」= 清单里的条目数;「实际文件」= 收到的文件中未被忽略的数量;「一致」= 路径、大小、SHA-256 都相同。
- 「已忽略」= 命中忽略列表而不参与核对的文件数,不计入上面任何一项。
- 「清单与文件一致」只在核对完整完成时显示;清单导入被拒绝时不产生结果。
- 日期取自 `?today` 或本机当天,只用于文件名和报告抬头。

## 已知限制

- 浏览器选目录依赖 `webkitdirectory`;拖入文件夹依赖 `webkitGetAsEntry`,不支持的浏览器只能选文件。
- 超大文件哈希慢(纯 JS 分块,速度取决于机器);整个文件夹的结果在内存中,数万个文件时只渲染前 500 条,导出含全部。
- 不校验权限、符号链接、空目录。
- 路径比较前做 NFC 规范化;只在大小写上不同的路径视为「大小写差异」,不处理其他等价写法。
- 不上传、不比较文件内容差异、不做目录同步。
