# 功能阶梯取舍板

## 定位
把功能按「门 1 自用 / 门 2 他人可用 / 门 3 付费」排成阶梯,用规则检查逼自己砍掉现在不该做的功能。纯前端,双击 `index.html` 即可用,数据只存本机浏览器(键名 `ladderboard.v1`)。

## 目标用户
独立开发者、小团队产品负责人。付款人:本人。

## 核心任务
1. 录入功能:功能名、一句话用户任务、所属门、MoSCoW、预计小时、依赖、验证层、状态。
2. 规则检查(每条带功能名):阻断与警告见下方「口径」。
3. 阶梯视图:三门三列,列内按 MoSCoW 分组;拖拽或用卡片上的按钮改门/等级;每列合计小时。
4. 过门证据:每门一段自填文本,留空即「未过门」;未过门时下一门功能整列标灰并提示「先拿证据」。
5. 导出:PRD 片段(.md)、功能表(.csv)、JSON 备份(可导入,校验不通过整份拒绝)。

## 如何打开
双击 `index.html`。「载入示例」会载入 16 个功能的「课后反馈工具」(合成示例,非真实数据)。

## 验证
- `node --test tests/core.test.cjs`(33 个用例)
- `node shots.cjs`(Playwright 走完整流程,70 条断言,产出 `screenshots/` 与 `showcase.png`)

- 「已砍」的 Must 不计入 Must 上限与验证层检查。
- 门 1 关键词检查只看未砍且非 Won't 的功能,匹配功能名 + 用户任务,不区分大小写;默认词表:登录、支付、数据库、服务端,可在页面改。
- 「依赖已砍/Won't」只检查未砍且非 Won't 的依赖方。
- 「门 3 早于门 2 排期」因没有排期字段,按两种情形判:门 2 功能依赖门 3 功能;门 3 功能已开工/已做而门 2 仍有未完成功能。
- 依赖环按强连通分量报告,每个环一条,列出环内功能(不保证给出先后路径)。
- 每列合计小时不含已砍和 Won't 功能。
- 导出 CSV 带 UTF-8 BOM 以便 Excel 识别中文;以 `= + - @` 开头(且长度大于 1)的字段加单引号前缀。
- 「已有数据」判断包含项目名、功能、过门证据和非默认关键词表;只改关键词时,「载入示例」「导入」会先确认,「清空数据」可执行并恢复默认词表。
- PRD 片段在有阻断时会附「未解决的阻断」小节。

- 表单草稿预览:表单里的所属门、优先级、工时、依赖、状态改动,在点保存前就重算看板、统计和规则检查,预览卡片带「预览(未保存)」;草稿不完整(例如工时不是数字)时看板仍显示已保存数据并说明原因。有未保存草稿时三个导出按钮停用。
- 界面把 MoSCoW 写成「必须做 Must / 应该做 Should / 可以做 Could / 本次不做 Won't」;导出文件仍用英文 Must/Should/Could/Won't(与 SPEC 一致)。
- 预计总小时 = 未砍且非「本次不做」功能的预计小时之和;「载入示例」后项目名带「(合成示例)」,导出文件名与内容沿用该标注。

## 已知限制
- 只支持单个项目;不估工期、不做甘特图。
- 拖拽依赖浏览器原生拖放,触屏设备请用卡片上的按钮。
- 导入必须是本工具导出的 JSON(format 与 version 严格匹配);字段不合法、id 重复、依赖指向不存在的功能都会整份拒绝。
- 浏览器禁用或写满本地存储时,页面显示「未保存」横幅并引导导出,刷新会丢失未导出的改动。
