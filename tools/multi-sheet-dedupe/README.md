# 多表重复记录核对

## 定位

把报名表、微信群导出、旧 CRM 等 1 到 5 张表放在一起,先标准化手机、邮箱、姓名、公司,再找出同一个人的多条记录,按记录组(一组包含被判定为同一人的记录)展示冲突字段,导出合并结果与冲突报告。不自动决定谁对谁错。

## 目标用户

小团队运营、社群运营、活动报名整理者(SPEC.md 写明的付款人:运营负责人)。

## 核心任务

1. 粘贴 CSV / TSV 或选本地文件添加表(自写 RFC 4180 解析器,自动识别逗号 / Tab / 分号),为每列选择含义:姓名 / 手机 / 邮箱 / 公司 / 微信号 / 其他(保留)/ 不使用,系统先按列名猜一遍。
2. 勾选匹配规则后点「开始核对」。
3. 在记录组面板看每组的所有记录,每组写明归组依据(命中的规则、两端的来源表与行号、标准化后的值),冲突字段琥珀色高亮;可改选主记录;「疑似」条目必须点「确认」才并入。
4. 导出合并结果 CSV、冲突报告 Markdown、原始记录加组号 CSV。

## 如何打开

- 双击 `index.html`(无需安装、联网、登录)。
- 数据存在当前浏览器的 localStorage(键 `dupcheck.v1`)。写入失败时页面顶部出现持续可见的「未保存」提示。
- 「载入示例」载入 3 张**合成示例**表共 40 条(虚构姓名、example.com 邮箱、138 0000 xxxx 号段)。已有表格、人工确认、手选主记录、改过的规则或没添加的粘贴草稿时,点「载入示例」会先出现一次页内替换确认(写明替换范围,取消则全部保留);「清空表格、规则和确认记录」同样先页内确认。
- 地址加 `?today=2026-10-20` 可固定导出文件名里的日期;不存在的日期(如 2026-02-30)会回退真实今天。

## 功能与规则

- 标准化(`core.js` 的 `normalize`):手机转半角、只留数字、去 `+86` / `0086` 前缀;邮箱小写去空格;中文姓名去所有空格(含全角),英文名首字母大写并合并空格;公司去「有限公司」「股份有限公司」「有限责任公司」「Ltd.」「Inc.」「Co.,Ltd.」后缀与空格。原值始终保留。
- 匹配:邮箱一致、手机一致、微信号一致、姓名加公司一致,各自可关;并查集传递合并(A~B、B~C 同记录组),记录组上列出每条连接的规则与两端记录,传递合并也能看出连接关系。空值不互相匹配。
- 疑似:姓名相同或相差一个字(标准化后,中文按字、英文按小写字母)编辑距离 ≤ 1(含单字姓名;增字、删字、替换都算),且两条记录的手机或邮箱至少一项有缺;只列出,人工确认后才并入,可撤销。内部用「删一个字符」分桶,避免 O(n²) 比较。
- 冲突:同一字段标准化后有两个以上不同非空值(含「其他」列同名列的不同值;未规定标准化规则的「其他」列区分大小写,AbC 与 abc 算冲突)。只有一方有值不算冲突。
- 主记录:默认非空字段最多的一条,可手改。合并:主记录优先,缺项用其他记录补,冲突值全部保留并用 ` / ` 连接,冲突列标出字段。
- 导出前一致性:表格、列映射或规则改动后结果标为过期,导出按钮禁用,重新核对后恢复。
- 导入校验:未闭合引号、引号后多余字符、数据行列数超过表头、表头重复、非 UTF-8 文件、超过 20000 行,一律整张拒绝并说明原因,不静默修正。浏览器里保存的旧数据校验不通过时也会提示并忽略。
- 导出防公式注入:CSV 与 Markdown 里以 `=`、`+`、`-`、`@` 开头的用户字段加单引号前缀(单独的 `-` 或 `+` 不算)。Markdown 表格另转义 `|`、换行与 `<`。
- 按名分组用 `Map`,`__proto__` / `constructor` 作为列名也安全。

## 口径
- 「N 条记录 → M 个记录组」:N 是所有表的数据行合计,M 是并查集合并后的组数;「含重复记录」指记录数大于 1 的组;「有冲突字段」指同一字段在组内有两个以上不同的标准化非空值。
- 导出始终覆盖全部记录组,不受界面「同时显示单条记录」「只看有冲突」筛选影响;导出提示写明各文件的行数(合并结果每组一行,原始记录每条一行,冲突报告只含有冲突的组)。
- 合成示例状态存进 localStorage,刷新后仍在:结果区持续显示「合成示例」标记,导出文件名带「合成示例-」前缀,CSV 多一列「数据来源」,冲突报告 Markdown 写明数据来源;添加你自己的表或清空后标记消失。
- 地址带合法 `?today=` 时页面顶部持续显示「基准日 …(由地址参数固定)」;它只影响导出文件名里的日期。
- innerHTML 核对:app.js 里 innerHTML 模板中的用户数据(表名、列名、单元格值、归组依据文字)全部经 `esc()` 转义,数字也统一包了 `esc()`;其余固定文案不含用户数据。

## 已知限制

- 相似匹配只做编辑距离 1,不做拼音或同音,不处理繁简差异。
- 合并结果仍需人工过目;不联网校验手机或邮箱真伪;不处理超过 20000 行。
- 数据按浏览器隔离,不同设备不互通;没有 JSON 备份,保留原始文件并导出结果即可。
- 只读 UTF-8 文本,Excel 的 .xlsx 与 GBK 的 CSV 需先另存为 CSV UTF-8。
- 手机号只做格式标准化,「手机一致」只比较标准化后的数字串,不识别座机分机。
- 组号按记录顺序生成,重新核对或确认疑似后组号可能变化。
- 没有 JSON 备份导入入口(见上),所以空状态下没有「导入备份」;换设备请重新粘贴原始表。
- 保存的是原始粘贴文本,接近 20000 行时可能超出浏览器存储,此时会出现「未保存」提示。
