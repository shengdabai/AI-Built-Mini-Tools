# SPEC · 10 多表重复记录核对

目标用户:小团队运营、社群运营、活动报名整理者。付款人:运营负责人。

## 核心任务(必须跑通)

1. 添加 1–5 个表(粘贴 CSV/TSV 或选本地文件;自写 RFC 4180 解析器,自动识别分隔符),每表显示表头并做列映射:姓名 / 手机 / 邮箱 / 公司 / 微信号 / 其他(可多列保留)。自动猜测列名。
2. 标准化(core 集中实现,每条可测):手机去空格、`-`、括号,`+86`/`0086` 前缀去掉,全角数字转半角,只留数字;邮箱小写、去空格;姓名去首尾空白、全角空格、中间空格(中文),英文名统一首字母大写、多空格合一;公司去 `有限公司`/`股份有限公司`/`Ltd.`/`Inc.` 后缀与空格后比较(原值保留)。
3. 匹配规则(可勾选,默认全开):邮箱完全一致;手机完全一致;微信号一致;姓名 + 公司一致;「疑似」= 姓名编辑距离 ≤ 1(中文按字、英文按小写字母)且手机或邮箱至少一项为空。用并查集合并成簇,簇内记录来自哪张表、哪一行。
4. 簇面板:每簇列出所有记录与字段,冲突字段(同一字段不同非空值)高亮;选主记录(默认最完整的一条:非空字段最多);「疑似」簇需人工确认才并入。
5. 导出:合并后的 CSV(每簇一行,主记录字段 + 其他记录的补充字段;冲突字段保留全部值用 ` / ` 连接并在「冲突」列标出);冲突报告 Markdown;原始记录加簇号的 CSV。公式前缀防护。

## 不做

不做自动决定谁对谁错;不联网校验手机/邮箱真实性;不处理超过 20000 行。

## core.js 暴露

`parseTable(text)`;`guessMapping(headers)`;`normalize.phone/email/name/company(s)`;`editDistance(a, b)`;`cluster(records, rules)` → `{clusters:[{id, members:[...], conflicts:[field], suspect:boolean}]}`;`pickMaster(cluster)`;`merge(cluster, masterIndex)`;`toCsv(rows)`;`conflictsToMarkdown(clusters)`。

## 示例

合成 3 张表共 40 条(报名表、微信群导出、旧 CRM),含:同一人手机写法不同(`+86 138-xxxx`)、邮箱大小写不同、姓名全半角空格、公司后缀差异、一对疑似(名字差一个字)、一簇三方冲突;全部为虚构姓名与 `example.com` 邮箱、`138 0000 xxxx` 号段;标注「合成示例」。

## 测试点(≥ 14)

各标准化函数(含边界:空值、全角);邮箱/手机/微信/姓名+公司四条规则;并查集传递合并(A~B、B~C → 同簇);疑似规则(编辑距离 1 且联系方式缺);冲突字段检测;pickMaster 规则;merge 输出字段与冲突列;分隔符识别;CSV 转义与公式防护;空表与单表不报错。

## 视觉方向

数据清洗工具感:中性灰白 + 一个蓝色强调;簇用卡片,冲突字段用琥珀底;手机端卡片单列。

## 已知限制(写进 README)

相似匹配只做编辑距离 1,不做拼音/同音;不处理繁简差异;合并结果仍需人工过目。
