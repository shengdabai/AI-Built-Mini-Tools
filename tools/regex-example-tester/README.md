# 正则样例验收

## 定位

先把「输入 + 期望」写下来,再逐条验证正则:匹配与否、捕获组、匹配位置,哪条不符、为什么不符,一眼看到。纯前端,双击 `index.html` 即可使用,不联网、不登录、无依赖。

## 目标用户
开发者、写表单校验规则的运营、做数据清洗的教师(见 SPEC.md)。

## 如何打开
双击 `index.html`(file:// 可用)。数据存在浏览器 localStorage,键 `regexcheck.v1`。

## 核心任务
1. 输入正则 + 标志(g/i/m/s/u) + 样例表,每行 `输入 | 匹配或不匹配 | 期望捕获1 | 期望捕获2`。
2. 点「运行验收」逐条执行,显示实际结果并对比,失败原因:应匹配但未匹配 / 不应匹配却匹配 / 捕获不符。
3. 安全:编译错误给出位置与原因;执行在 Worker 里,单条超过 2 秒判「疑似灾难性回溯」并中止,其余样例继续;运行中可点「停止验收」立即终止;输入长度上限可配(默认 10000)。
4. 解释:把正则拆成 token 并给中文说明,不认识的标「未解析」。
5. 导出:样例表 CSV(可再导入)、验收报告 Markdown、JSON 备份。
6. 样例库:本机保存多个「正则 + 样例集」,命名、搜索。

内置 5 套合成示例(手机号、邮箱、日期、身份证前 6 位、疑似回溯 `(a+)+$`),每套含故意写错的期望。

## 口径(SPEC 未规定,本实现的选择)
- 「匹配」指在输入中能找到匹配(exec),不是整串匹配;要整串请自己写 `^…$`。
- 标志 g 时只验首个匹配,另显示总数;每次执行前后 lastIndex 复位。
- 期望捕获按顺序只比较写出的那几组;`(未捕获)` 表示该组应为 undefined,空字段表示空字符串;正则实际组数少于写出的组数算不符;多出的实际组不检查。「不匹配」样例写的捕获被忽略。
- 样例表字段两侧各去掉一个空格(导出用 ` | ` 连接,所以往返无损);想测首尾空格就多写一个。`\|` 是字面竖线,不支持其他转义。
- CSV:「期望捕获」列未指定捕获为空单元格,指定了(含空捕获 `[""]`)为 JSON 数组串,二者可区分;UTF-8 带 BOM;用户字段以 `=` `+` `-` `@` 开头时加单引号前缀(单独的 `-`/`+` 不加),再导入时还原;导入要求表头以「输入,期望」开头,引号未闭合、非法期望、含换行的行都会让整份被拒绝。导出报告里的表格同样防公式并转义竖线。
- JSON 备份导入:类型、枚举、ID 唯一性、标志、currentId 任一不合法即整份拒绝;URL 字段不存在。
- 输入长度上限范围 1 到 10000000 的整数(草稿保存与读取用同一个 `validateState`)。
- 编译错误位置由自带扫描器推断(0 起始内部,界面显示第 N 个字符),找不到时只给原因。
- 停止验收:点「停止验收」会终止当前 Worker,已有结果保留,没跑完的样例标为「未运行」。未运行不算通过也不算失败;通过率的分母只算已运行的条数,并写明「已运行 X/N 条」。报告和 CSV 都单独标出未运行。
- 「已有数据」(载入示例、导入备份、清空前要确认)= 名称、正则、样例表、样例库任一非空,或标志不是空、或输入长度上限不是默认的 10000。确认文案写明草稿的标志、上限、样例表行数和样例库条数。
- 本产品不涉及日期,未实现 `?today`。

## 已知限制
- 解释器只覆盖常见语法;回溯检测靠超时,不是静态分析。
- 样例输入不能含换行(行格式限制),所以 m/s 标志只能测单行文本;界面在标志旁和样例表旁都有说明。
- 样例捕获里字面的 `(未捕获)` 无法表达。
- 超时只中止单条,每条最长等 2 秒,多条回溯样例会累加等待;可以随时点「停止验收」。
- Worker 以 Blob 方式启动;若浏览器禁止,会报错而不是改用主线程(避免卡死)。
- 运行结果不持久化,刷新后需重新运行。
