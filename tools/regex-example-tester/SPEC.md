# SPEC · 33 正则样例验收

灵感:李笑来公开文章中的相关概念(本工具是作者的理解,不代表其本人观点)。目标用户:开发者、运营写表单校验规则的人、教师做数据清洗。付款人:本人。

## 核心任务(必须跑通)

1. 输入:正则表达式 + 标志(g/i/m/s/u);样例表:每行 `输入 | 期望(匹配/不匹配)| 期望捕获(可选,用 | 分隔多组)`。
2. 运行:逐条执行,显示实际结果(匹配与否、捕获组、匹配位置),与期望对比:通过/失败;失败原因(应匹配未匹配 / 不应匹配却匹配 / 捕获不符)。
3. 安全:正则编译错误给出位置与原因;执行用超时保护(在 Worker 里跑,超过 2 秒判「疑似灾难性回溯」并中止;core.js 提供同步版供测试,app.js 用 Worker);输入长度上限(可配)。
4. 解释:把正则拆成 token 列表(字符类、量词、分组、锚点、转义)并给中文说明(自写简单解析器,只覆盖常见语法,不支持的 token 标「未解析」)。
5. 导出:样例表 CSV(可再导入);验收报告 Markdown(正则 + 通过率 + 失败清单);JSON 备份。
6. 样例库:本机保存多个「正则 + 样例集」,命名、搜索。

## 不做

不做正则生成、不做可视化铁路图、不联网。

## core.js 暴露

`compile(pattern, flags)` → `{ok, re|error, pos?}`;`runCase(re, input, expect)` → `{pass, actual, reason}`;`runAll(pattern, flags, cases)` → `{results, stats}`;`parseCases(text)`;`tokenize(pattern)` → `[{type, raw, explain}]`;`toCsv`;`reportToMarkdown`;`validateImport`。

## 示例

合成 4 套:手机号(11 位)、邮箱(简化)、日期 `YYYY-MM-DD`、身份证前 6 位;每套 8–10 条样例,含故意失败项;另有一条演示「疑似回溯」的正则 `(a+)+$` 与长输入(在页面里由 Worker 中止);标注「合成示例」。

## 测试点(≥ 12)

compile 错误位置;runCase 三种失败原因;捕获组对比(含未捕获 undefined);标志 g 时 lastIndex 复位;parseCases 分隔与转义(`\|`);stats 通过率;tokenize 常见语法(字符类、量词 `{m,n}`、分组、命名组、锚点、转义、未解析);CSV 公式防护;validateImport;空样例;超长输入拒绝(同步版)。

## 视觉方向

开发工具感:深色主题(炭灰底,AA);通过绿 / 失败红 + 图标;手机端单列。

## 已知限制(写进 README)

解释器只覆盖常见语法;回溯检测靠超时,不是静态分析。
